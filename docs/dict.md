# Большой словарь (`/dict`)

Открытая страница вне оболочки `/korean` (как `/history`): поиск по всему корейско-русскому словарю 한국어기초사전 и страница каждого слова `/dict/<слово>`. Свой словарь платформы (`frontend/src/data/korean/dictionary.ts`) от него не зависит.

## Откуда данные

- Источник: 한국어기초사전 (국립국어원), архив `spellcheck-ko/korean-dict-nikl-krdict`, **снимок 2019-08-02**, лицензия **CC BY-SA 2.0 KR**. Аудио в данных нет. Автор, архив, лицензия и «снимок 2019 года» подписаны внизу каждой страницы словаря (`components/dict/DictShell.vue`, `data/korean/dictSource.ts`), это требование лицензии, не убирать.
- Файл `krdict_ko_ru.json` (76 МБ, 54 828 записей) **в git не лежит** (вес и лицензия). Локально он в `материалы/словарь-krdict/`, на сервер кладётся вручную: `scp krdict_ko_ru.json <сервер>:<папка с данными>/` (в Docker это том `/data`, путь `/data/krdict_ko_ru.json`; другой путь в `DICT_FILE`).
- В индекс попадают записи с русским переводом или хотя бы русским описанием: 53 149 из 54 828. Записей вообще без русского нет в индексе.

## Индексация (Meilisearch, индекс `krdict`)

- Автоматически: при старте сервера, если файл лежит на месте, а индекса ещё нет (`DictService.onApplicationBootstrap`, в фоне, около 15 секунд).
- Вручную без сервера: `MEILISEARCH_URL=… MEILISEARCH_MASTER_KEY=… node scripts/dict-index.mjs [файл]` (нужна сборка сервера `npm run server:build`; локально файл берётся из `материалы/…`).
- Вручную через API (только владелец): `POST /api/dict/reindex`; состояние `GET /api/dict/status`.
- Преобразование записи в документ: `backend/src/dict/dict.data.ts` (часть речи и уровень по-русски, примеры по видам: предложения `sent`, словосочетания `phr`, диалоги `dial`; из примеров берётся не больше 6, 12 и 3). Настройки индекса: `DictService.reindex` (ищем по слову, спряжённым формам, переводу и определению в таком порядке; затем выше слова высокого уровня и короткие).
- Поменял формат документа или настройки: переиндексируй (индекс собирается заново с нуля).

## API (`backend/src/dict`)

- `GET /api/dict/search?q=&level=&pos=&offset=` (открытый): 20 записей, `facets` (сколько слов в каждом уровне и части речи) для кнопок-фильтров. В записях только первые 4 значения и по одному примеру (`moreSenses` сколько ещё), остальное на странице слова. Каждая запись krdict это отдельное слово (омонимы отдельными записями).
- **Поиск по спряжённым формам** (`dict.hangul.ts`, `dictionaryForms`): если набрано `먹었어요`, `예뻐요`, `더워요`, `몰라요`, сервер угадывает словарные формы (먹다, 예쁘다, 덥다, 모르다), ищет их среди глаголов и прилагательных и ставит первыми, а сверху страницы пишет подсказку. Если слово и так есть в словаре в таком виде (비빔, 학생), догадок нет.
- `GET /api/dict/word/:слово` (открытый): все омонимы слова целиком (все значения и примеры) и слова, в которых оно содержится.
- Meilisearch по корейскому ищет слогами и по началу слова: `비빔` находит `비빔밥`, но не находит слово по середине (`밥` не найдёт `비빔밥` по слову, только по определению и переводу).

## Страница слова (`views/DictWordView.vue`)

Статья грузится на сервере (`useFetch`). Вкладки показываются только если есть данные:
- **Спряжение** (глагол, прилагательное) или **С частицами** (существительное): `frontend/src/lib/conjugate.ts`, формы строит по правилам, знает ㅂ, ㄷ, ㅅ, 르, ㅎ, ㅡ, ㄹ и 하다; редких исключений не знает, на странице пометка. Тест `tests/conjugate.test.mjs`. Рядом «В словаре отмечены»: формы из самой базы.
- **Примеры, Словосочетания, Диалоги**: из базы. Переводов примеров в базе нет (в каждом примере только корейский текст и тип), поэтому по-русски они не показываются.
- **Связанные слова**: слова из базы, в которых содержится это слово.
- **Только данные базы и формы по правилам.** Своих текстов (грамматика, синонимы, советы, переводы примеров) на странице нет по решению владельца (2026-11-08): добавлять только по его слову.

## Что ещё в поиске

- Фильтры по уровню (начальный, средний, высокий, без уровня) и по части речи, «Показать ещё» (до 2000 записей на запрос).
- Владельцу (после входа по токену) на карточке кнопка «Записать слово»: слово уходит во «входящие» шторки «Новые слова» (`stores/newWords.ts`), дальше обычный порядок (он записал → Claude читает → сверка → обсуждение → добавление).
- Страницы слов `/dict/<слово>` открыты для поисковиков (владелец так решил), но в карту сайта не входят: их 53 тысячи, до них доходят по ссылкам из поиска и «Связанных слов». Заголовок и описание по слову строит `seoFor` (`data/seo.ts`). Нужна карта сайта со словами: отдельная задача (sitemap-индекс).

## Правила

- Слова в словарь платформы отсюда не переносить без слова владельца.
- Менял `dict.data.ts`, настройки индекса или `conjugate.ts`: переиндексируй и прогони `npx --prefix backend vitest run test/dict.spec.ts` и `node --test tests/conjugate.test.mjs`.
