# Большой словарь (`/dict`)

Открытая страница вне оболочки `/korean` (как `/history`): поиск по всему корейско-русскому словарю 한국어기초사전 и страница каждого слова `/dict/<слово>`. Свой словарь платформы (`frontend/src/data/korean/dictionary.ts`) от него не зависит.

## Откуда данные

- Источник: 한국어기초사전 (국립국어원), архив `spellcheck-ko/korean-dict-nikl-krdict`, **снимок 2019-08-02**, лицензия **CC BY-SA 2.0 KR**. Аудио в данных нет. Автор, архив, лицензия и «снимок 2019 года» подписаны внизу каждой страницы словаря (`components/dict/DictShell.vue`, `data/korean/dictSource.ts`), это требование лицензии, не убирать.
- Файл `krdict_ko_ru.json` (76 МБ, 54 828 записей) **в git не лежит** (вес и лицензия). Локально он в `материалы/словарь-krdict/`, на сервер кладётся вручную, один раз (в Docker это том `app-data`, внутри контейнера `/data/krdict_ko_ru.json`; другой путь в `DICT_FILE`):
  ```
  scp материалы/словарь-krdict/krdict_ko_ru.json сервер:/tmp/
  docker compose cp /tmp/krdict_ko_ru.json backend:/data/krdict_ko_ru.json
  docker compose restart backend
  ```
  После перезапуска сервер сам построит индекс (около полминуты), потом словарь заработает. Файл лежит в томе, при обновлении сайта он остаётся.
- В индекс попадают записи с русским переводом или хотя бы русским описанием: 53 149 из 54 828. Записей вообще без русского нет в индексе.

## Индексация (Meilisearch, индекс `krdict`)

- Автоматически: при старте сервера, если файл лежит на месте, а индекс не готов (`DictService.onApplicationBootstrap`, в фоне, около 15–30 секунд, пока идёт сборка, поиск отвечает «словарь сейчас индексируется»). Готовым индекс считается только по пометке `krdict_ko_ru.json.indexed` рядом с файлом (размер и время файла, число слов и версия формата `INDEX_VERSION` в `dict.service.ts`: меняешь поля документа или настройки индекса, поднимай её, и на сервере индекс сам соберётся заново при старте): её пишет успешная сборка и стирает начало новой. Поэтому недостроенный индекс (сервер перезапустили на середине) доделывается при следующем старте; файл заменили, он тоже переиндексируется сам. Сообщения о ходе идут в обычный лог (`docker compose logs backend | grep -i словар`).
- Вручную без сервера: `MEILISEARCH_URL=… MEILISEARCH_MASTER_KEY=… node scripts/dict-index.mjs [файл]` (нужна сборка сервера `npm run server:build`; локально файл берётся из `материалы/…`).
- Вручную через API (только владелец): `POST /api/dict/reindex`; состояние `GET /api/dict/status`.
- Преобразование записи в документ: `backend/src/dict/dict.data.ts` (часть речи и уровень по-русски, примеры по видам: предложения `sent`, словосочетания `phr`, диалоги `dial`; из примеров берётся не больше 6, 12 и 3). Настройки индекса: `DictService.reindex` (ищем по слову, спряжённым формам, переводу и определению в таком порядке; затем выше слова высокого уровня и короткие).
- Поменял формат документа или настройки: переиндексируй (индекс собирается заново с нуля).

## API (`backend/src/dict`)

- `GET /api/dict/search?q=&level=&pos=&offset=` (открытый): 20 записей, `facets` (сколько слов в каждом уровне и части речи) для кнопок-фильтров. В записях только первые 4 значения и по одному примеру (`moreSenses` сколько ещё), остальное на странице слова. Каждая запись krdict это отдельное слово (омонимы отдельными записями).
- **Поиск по спряжённым формам** (`dict.hangul.ts`, `dictionaryForms`): если набрано `먹었어요`, `예뻐요`, `더워요`, `몰라요`, сервер угадывает словарные формы (먹다, 예쁘다, 덥다, 모르다), ищет их среди глаголов и прилагательных и ставит первыми, а сверху страницы пишет подсказку. Если слово и так есть в словаре в таком виде (비빔, 학생), догадок нет.
- `GET /api/dict/word/:слово` (открытый): все омонимы слова целиком (все значения и примеры) и слова, в которых оно содержится.
- Meilisearch по корейскому ищет слогами и по началу слова: `비빔` находит `비빔밥`, но не находит слово по середине (`밥` не найдёт `비빔밥` по слову, только по определению и переводу).

## Порядок слов в поиске и меню «Все слова»

- **Частотный список (`freq`, `grade`):** в krdict частот нет, поэтому подключён официальный «한국어 학습용 어휘 목록» Национального института корейского языка (5 965 слов, рейтинг по «현대 국어 사용 빈도 조사», лицензия 공공누리 типа 1: указывать источник, это сделано внизу страниц подборок). Файл скачан со страницы https://www.korean.go.kr/front_eng/down/down_02V.do?etc_seq=70, превращён скриптом `scripts/build-vocab.mjs <файл.txt>` в `backend/src/dict/dict.vocab.ts` (руками не править). `applyVocab` (`dict.data.ts`) ставит слову место в списке: сначала по слову и части речи, потом по одному слову; омонимы получают рейтинг только у записи с меньшим номером. Сопоставилось 5 845 слов. Слова из списка получают прибавку к `rank` (до +100).
- **«Популярность» слова (`rank`, `rankOf` в `dict.data.ts`):** для слов вне частотного списка оценка по тому, что есть: уровень (начальный 300, средний 200, высокий 100), число значений, число примеров, короткое слово (+), окончания, приставки и устойчивые выражения (−). Индекс сортирует по ней при равной релевантности.
- **Точное совпадение идёт первым:** при запросе слова целиком или одного из переводов (поле `tr`: переводы по одному из двух главных значений) такие слова поднимаются наверх по убыванию `rank` (`DictService.topMatches`). Поэтому «школа» даёт 학교, а не «школа с агропромышленным уклоном», «вода» даёт 물, «друг» даёт 친구.
- **Меню слева «Все слова»** (`components/dict/DictWordList.vue`, `GET /api/dict/folders` и `GET /api/dict/list`): «папки» (вариант №10 «Папки по уровням» выбран владельцем 2026-11-08). Папки: «Все слова», по уровню (начальный, средний, высокий, без уровня) и по части речи (существительные, глаголы, прилагательные, наречия и остальные, самые большие первыми). Папка раскрывается и грузит 40 слов, внутри кнопка «Ещё слова». Вверху переключатель «популярные» / «по алфавиту». Нажал слово: в центре его карточка (выбор хранится в `?w=` адреса), с карточки переход на страницу слова. На телефоне меню открывается кнопкой «Все слова».
- Правило `pagination.maxTotalHits` индекса равно 60 000 (нужно меню); в поиске выдача всё равно ограничена 2000 записей.

## Подборки слов (`/dict/podborki`, `/dict/podborki/<slug>`)

- Описание подборок: `backend/src/dict/dict.collections.ts` (адрес, заголовок, описание для поисковика, вступление, фильтр Meilisearch, размер). Сейчас 13: `top-100`, `top-500`, `top-1000` (самые частые по `freq`), `glagoly`, `prilagatelnye`, `narechiya` (начальный уровень по частям речи), темы по категориям базы (`cat`): `vremya`, `chisla`, `eda`, `emocii`, `semya`, `telo`, `cveta`.
- Порядок в подборке: сначала по `freq` (место в частотном списке), у слов без него по `rank`. Новую подборку добавляй записью в `COLLECTIONS` (тест следит за адресом, длиной описания и фильтром); в карту сайта она попадёт сама (`DictService.sitemap`).
- API: `GET /api/dict/collections` (список с числом слов) и `GET /api/dict/collection/:slug` (слова с двумя главными переводами, кэш час). Страницы `views/DictCollectionsView.vue` и `DictCollectionView.vue`: заголовок и описание из подборки, JSON-LD `CollectionPage` + `ItemList` + `BreadcrumbList` (`collectionJsonLd` в `lib/dictSeo.ts`), 404 для несуществующей. Со страницы `/dict` ведёт строка ссылок «Подборки».

## Страница слова (`views/DictWordView.vue`)

Статья грузится на сервере (`useFetch`). Вкладки показываются только если есть данные:
- **Спряжение** (глагол, прилагательное) или **С частицами** (существительное): `frontend/src/lib/conjugate.ts`, формы строит по правилам, знает ㅂ, ㄷ, ㅅ, 르, ㅎ, ㅡ, ㄹ и 하다; редких исключений не знает, на странице пометка. Тест `tests/conjugate.test.mjs`. Рядом «В словаре отмечены»: формы из самой базы.
- **Примеры, Словосочетания, Диалоги**: из базы. Переводов примеров в базе нет (в каждом примере только корейский текст и тип), поэтому по-русски они не показываются.
- **Связанные слова**: слова из базы, в которых содержится это слово.
- **Только данные базы и формы по правилам.** Своих текстов (грамматика, синонимы, советы, переводы примеров) на странице нет по решению владельца (2026-11-08): добавлять только по его слову.

## Что ещё в поиске

- Фильтры по уровню (начальный, средний, высокий, без уровня) и по части речи, «Показать ещё» (до 2000 записей на запрос).
- Владельцу (после входа по токену) на карточке кнопка «Записать слово»: слово уходит во «входящие» шторки «Новые слова» (`stores/newWords.ts`), дальше обычный порядок (он записал → Claude читает → сверка → обсуждение → добавление).
- Страницы слов `/dict/<слово>` открыты для поисковиков (владелец так решил) и **входят в карту сайта**: `GET /api/dict/sitemap` отдаёт около 44 600 адресов (по одному на слово, выражения с пробелами не берутся), Nuxt режет их на куски по 10 000 (`/sitemap_index.xml`), подробности в `docs/home-and-theme.md`. Заголовок и описание по слову строит `seoFor` (`data/seo.ts`). Каждая страница слова рисуется на сервере (SSR) из API: готовый HTML с переводом и значениями, поэтому поисковик видит её содержимое.

## Правила

- Слова в словарь платформы отсюда не переносить без слова владельца.
- Менял `dict.data.ts`, настройки индекса или `conjugate.ts`: переиндексируй и прогони `npx --prefix backend vitest run test/dict.spec.ts` и `node --test tests/conjugate.test.mjs`.

## SEO (подробный план и что нужно от владельца: `материалы/сео/ПЛАН.md`, не в git)

Тест `tests/dict-seo.test.mjs`.
- **Страница `/dict`:** заголовок «Корейско-русский словарь онлайн…», блок «Популярные слова» (48 ссылок из `GET /api/dict/list`, рисуется на сервере), `SearchAction` на сайте (`app.vue`). Адреса с `?q=`, `?w=`, фильтрами: `noindex, follow`.
- **Скорость:** `routeRules` `/dict` и `/dict/**` с `swr: 3600` (в разработке выключено, иначе виден старый HTML); API отдаёт `Cache-Control` (слово 1 час, список и карту сайта по 5–60 минут); фон страницы в двух размерах (`assets/dict/bg.webp` 1774 px и `bg-sm.webp` 900 px для телефона) с `preload`.
- **Слова той же темы** на странице слова: `similar` из `GET /api/dict/word/:слово` (поле `cat`, «semantic_category» из базы).
- **IndexNow** (`scripts/indexnow.mjs`, ключ `frontend/public/<ключ>.txt`, публичный по замыслу протокола): `node scripts/indexnow.mjs --dry` показывает, что будет отправлено; без `--dry` адреса из `sitemap_index.xml` порциями по 10 000 уходят на `https://yandex.com/indexnow` (получают Яндекс, Bing и остальные участники). Сначала ключ должен открываться на сайте (скрипт сам проверяет). Исходящие запросы: запускать только по слову владельца. Тест `tests/indexnow.test.mjs`.
