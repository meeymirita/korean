# Помощник: чат с вопросами по корейскому (`/korean/chat`)

Пишешь вопрос, получаешь ответ по-русски. Работает через **бесплатные модели OpenRouter** (OpenAI-совместимый `POST /chat/completions`; Gemini не подошёл из-за ошибки доступа).

## Доступ
Только владелец: сервер `@Owner()` (гость 403, без токена 401), раздел с `owner: true` в `sections.ts` скрыт у гостя, страница закрыта токеном, `noindex`.
Ключ только в `.env` проекта, на сайт не попадает. **Никогда не вставлять ключ в чат и репозиторий** (выделение строки с ключом в редакторе тоже отправляет её в переписку): ключ, попавший в чат, перевыпустить.
Ключу в OpenRouter стоит поставить маленький лимит (Limit = 1): используем только бесплатные модели.

## Настройки (`.env` проекта, образец `.env.example`)
| Переменная | По умолчанию | Что делает |
|---|---|---|
| `OPENROUTER_API_KEY` | пусто | ключ с openrouter.ai/keys; без него `POST /api/chat` отвечает 503, страница пишет «не подключён» |
| `CHAT_MODEL` | `openrouter/free` | модель; сейчас `nvidia/nemotron-3-ultra-550b-a55b:free` (бесплатные оканчиваются на `:free`) |
| `CHAT_DAILY_LIMIT` | 40 | вопросов в сутки (по UTC); у бесплатного тарифа OpenRouter 20 в минуту и 50 в день |
| `CHAT_BASE` | `https://openrouter.ai/api/v1` | адрес API (в тестах подменяется) |
После изменения `.env` перезапусти службу (`docker compose up -d backend` пересоздаст контейнер с новыми значениями).

## Как устроено
- **Сервер** `backend/src/chat/`: `chat.service.ts` проверяет переписку (роли `user`/`assistant`, до 2000 знаков, в модель уходят последние 12), считает суточный лимит (в памяти),
  при пустом ответе повторяет один раз, ошибки вопрос не списывают (таймаут 40 с). `chat.controller.ts`: `GET /api/chat` → `{configured, model, limit, left}`, `POST /api/chat` → `{reply, left}`
  (ошибки: 400, 404, 429, 502, 503). **История чатов хранится в базе** (с 2026-11-17, таблицы `chat_convs` и `chat_msgs`, миграция `20261117120000_chat_history`, только новые таблицы): в `POST /api/chat` поле `conv` (`'new'` завести чат, номер чата дописать в него, без поля ничего не сохранять; в ответе приходит `conv`), `GET /api/chat/conversations` (список, новые сверху, до 200), `GET /api/chat/conversations/:id` (сообщения), `DELETE /api/chat/conversations/:id`. В чате не больше 300 сообщений (`CHAT_MAX_SAVED`), дальше ошибка `chat too long` и предложение начать новый; несуществующий чат даёт 404 до обращения к модели (вопрос не тратится). Заголовок чата это начало первого вопроса (80 знаков). В модель по-прежнему уходят последние 12 сообщений.
- **Сайт:** `src/lib/chat.ts` (запросы, понятные ошибки, безопасный показ ответа без HTML, `koreanParts`), `src/views/korean/ChatView.vue` (переписка с сервера, номер открытого чата в `sessionStorage` (`ui_chat_conv`), после обновления страницы открывается тот же чат; кнопка **«＋ Новый чат»** закрывает текущий (он остаётся в истории), список **«История чатов»** открывает прежний чат или удаляет его с подтверждением; счётчик «осталось N из 40», Enter отправляет, Shift+Enter новая строка). Ответ показывается оформленным (`richReply` в `lib/chat.ts`): корейская фраза с переводом «фраза — перевод» карточкой, подзаголовки («Правило:»), нумерация, «Попробуй…» плашкой, хангыль внутри текста выделен шрифтом и цветом. Кнопка **«Разобрать»** под ответом прогоняет корейские фразы через `SentenceBreakdown` (чтение и перевод слов берёт из словаря сайта).
- **Инструкция модели** (`prompt.ts`): ответы по-русски и коротко; свои примеры и упражнения только из пройденного, но **на любой вопрос ученика отвечать всегда**, в том числе про непройденное (одна пометка «это пока не пройдено», без отказов и «будет позже»; решение владельца 2026-11-17); будущее время `-(으)ㄹ 거예요` и `만` пройдены (раньше инструкция ошибочно считала их непройденными и отвечала «это будет позже»); примеры из словаря ученика;
  **чтение не писать** (модель ошибалась; его считает сайт); каждая корейская фраза отдельной строкой; пол ученика неизвестен; не выдумывать слова и правила; только про корейский.
  Списки пройденных тем и слов подставляются из `curriculum.ts`: после изменения словаря, отметки уроков пройденными или карточек-заглушек «впереди» (`ahead` в `grammar.ts`) запусти `npm run sync` и закоммить результат (иначе упадут `tests/sync.test.mjs` и `tests/chat-prompt.test.mjs`).

## Что известно о качестве
`openrouter/free` (автовыбор) ошибался в частицах и чтении, не годится. `nvidia/nemotron-3-ultra-550b-a55b:free` на проверочном наборе ответила верно, но бесплатная модель всё равно может ошибаться
в редких словах: ответам не верить без сверки с «Грамматикой» и учителем (написано и на странице). Бесплатные модели могут хранить тексты вопросов: «личного не пиши».

## Общая история «Разговоры» (`/korean/talks`, с 2026-11-17)
Один список чатов с помощником и голосовых разговоров (`docs/voice.md`) с поиском по тексту всех реплик. Сервер `backend/src/talks/` (`GET /api/talks?q=`, только владелец; без `q` или короче двух знаков 150 последних, с `q` поиск без учёта регистра по `chat_msgs`, `voice_messages` и названиям чатов, у результата кусок текста вокруг совпадения и число совпадений; голосовой разговор без единой реплики не показывается). Сайт `views/korean/TalksView.vue` + `lib/talks.ts`: поиск с паузой 300 мс, найденное выделено; нажатие на чат открывает `/korean/chat?c=<номер>`, на голосовой разговор окно голоса на вкладке «История». Со страницы помощника ссылка «Все разговоры и поиск →». Тесты: `tests/talks-server.test.mjs` (нужна база), `backend/test/talks.spec.ts`, `frontend/test/talks.spec.ts`.
