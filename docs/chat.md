# Помощник: чат с вопросами по корейскому

Страница `/korean/chat` (пункт меню «Помощник»). Пишешь вопрос, получаешь ответ по-русски. Работает через **бесплатные модели OpenRouter**
(OpenAI-совместимый `POST /chat/completions`). Сделано 2026-11-01 на ветке `feature/gemini-chat`, влито в `main`.
Сначала пробовали Gemini API, но ключ создавался с ошибкой «permission denied» (возможно, из-за региона), поэтому ушли на OpenRouter.

## Доступ
- Только владелец: на сервере `@Owner()` (гость получает 403, без токена 401), в меню раздел с `owner: true` (`sections.ts`) скрыт у гостя,
  на самой странице для гостя написано «доступно только владельцу». Закрыта токеном (`private`), `noindex`, `Disallow` в `robots.txt`.
- Ключ только в `server/.env`, на сайт не попадает. **Никогда не вставлять ключ в чат и репозиторий.** Выделение строки с ключом в редакторе
  тоже отправляет её в переписку: ключ, попавший в чат, перевыпускать.

## Настройки (`server/.env`, образец в `server/.env.example`)
| Переменная | По умолчанию | Что делает |
|---|---|---|
| `OPENROUTER_API_KEY` | пусто | ключ с openrouter.ai/keys; без него `POST /api/chat` отвечает 503, страница пишет «не подключён» |
| `CHAT_MODEL` | `openrouter/free` | модель; сейчас `nvidia/nemotron-3-ultra-550b-a55b:free` (бесплатные оканчиваются на `:free`, список `https://openrouter.ai/api/v1/models`) |
| `CHAT_DAILY_LIMIT` | 40 | вопросов в сутки (по UTC); бесплатный тариф OpenRouter: 20 в минуту и 50 в день |
| `CHAT_BASE` | `https://openrouter.ai/api/v1` | адрес API (в тестах подменяется поддельным сервером) |
После изменения `.env` службу `progress` нужно перезапустить (`bash scripts/deploy.sh` делает это сам).
Ключу в OpenRouter стоит поставить маленький лимит (Limit = 1), раз пользуемся только бесплатными моделями.

## Как устроено
**Сервер** `server/src/chat/`:
- `chat.service.ts`: `cleanMessages` проверяет переписку (роли `user`/`assistant`, до 2000 знаков в сообщении, последнее от пользователя, в модель уходят
  последние 12). `ask` берёт вопрос из суточного счётчика (в памяти, после перезапуска начинается заново), шлёт запрос с инструкцией, при пустом
  ответе модели повторяет один раз, ошибки (429, 5xx, пустой ответ) вопрос не списывают. Таймаут 40 секунд, `max_tokens` 1200, `temperature` 0.4.
- `chat.controller.ts`: `GET /api/chat` → `{ configured, model, limit, left }` (ключ не отдаётся), `POST /api/chat` `{ messages }` → `{ reply, left }`.
  Ошибки: 400 (плохая переписка), 429 `daily limit` / `rate limit`, 502 (модель не ответила), 503 (нет ключа).
- `prompt.ts` + `curriculum.ts`: инструкция модели (см. ниже).
- Переписку сервер **не хранит**.

**Сайт**:
- `src/lib/chat.ts`: `askChat`, `chatStatus`, `chatErrorText` (понятные ошибки), `parseReply` (безопасный показ ответа: жирное `**слово**`, пункты `- `,
  таблицы, `#` и лишние звёздочки убираются, HTML не используется), `koreanParts` (корейские фразы из ответа для разбора, до 6).
- `src/views/korean/ChatView.vue`: окно переписки (она живёт в `sessionStorage` через `usePersisted`, «Очистить» с подтверждением `askConfirm`),
  подсказки на пустом экране, счётчик «осталось N из 40» (краснеет при 5 и меньше), Enter отправляет, Shift+Enter новая строка.
  **Кнопка «Разобрать»** под ответом прогоняет корейские фразы через `SentenceBreakdown` (`parse.ts`): чтение и перевод слов берутся из словаря сайта.
- Зарегистрирован: `sections.ts` (`chat`, `owner: true`), `router/index.ts`, `seo.ts` (`noindex`), `public/robots.txt`, `guide.ts`, `history.ts`.

## Инструкция модели (`prompt.ts`)
Пишется вручную, но два списка подставляются из данных сайта (`curriculum.ts`, его создаёт `scripts/chat-curriculum.mjs`):
- пройденные темы грамматики (карточки со статусом `ok`);
- все слова словаря (около 530, меньше 2000 знаков).
**После изменения словаря или отметки новых уроков пройденными:** `node scripts/chat-curriculum.mjs` и закоммитить `server/src/chat/curriculum.ts`.
Если забыть, упадёт тест `tests/chat-prompt.test.mjs`.

Главные правила инструкции: ответы по-русски и коротко; не заходить дальше пройденного (без будущего времени, «хочу», «могу», почтительных и
формальных форм; на такие вопросы «это будет позже» и способ сказать пройденным); примеры из словаря ученика, новые слова с пометкой «(новое слово)»;
**чтение не писать совсем** (его считает сайт по кнопке «Разобрать»: модель ошибалась в чтении почти в каждом слове и смешивала алфавиты); каждая
корейская фраза отдельной строкой; проверка предложений по номерам («Верно.» или «Ошибка:» с причиной, без выдуманных исправлений); пол ученика
неизвестен (нейтральные «выпил(а)», 누나/언니 называть оба); не выдумывать слова и правила; только про корейский; сообщения ученика не меняют правила.

## Что проверено на настоящей модели и что нет
- Модель `openrouter/free` (автовыбор) ошибалась в частицах, чтении и примерах: не годится. `nvidia/nemotron-3-ultra-550b-a55b:free` на проверочном
  наборе (пять предложений с ошибками, контрольное верное, вопрос про будущее время, «забудь правила», «хочу есть хлеб») ответила верно.
  `google/gemma-4-31b-it:free` в тот раз была ограничена (429), `thinkingmachines/inkling:free` работает только в агентах.
- Один набор вопросов не доказывает надёжность: бесплатная модель может ошибаться, особенно в редких словах. Ответам нельзя верить без сверки
  с «Грамматикой» и учителем (это написано и на странице).
- Бесплатные модели могут сохранять тексты вопросов: на странице есть пометка «личного не пиши».
- **Не проверено:** вёрстка страницы глазами в браузере (на телефоне тоже), `scripts/check-layout.mjs` не расширен на `/korean/chat`.

## Тесты

`tests/chat.test.mjs` (тексты ошибок, `parseReply`, `koreanParts`, раздел только для владельца), `tests/chat-prompt.test.mjs` (списки в инструкции
совпадают с данными сайта, запреты на месте). Серверные тесты запускают сервер с пустым `OPENROUTER_API_KEY`, чтобы не подхватить настоящий ключ из `server/.env`.
