# Голосовой собеседник

Код написан 2026-11-16 в ветке **`feature/voice`** (в `main` не слит, на сайт не выложен). Идея владельца: кнопка сверху и окно как у музыкального плеера (`docs/music.md`), внутри микрофон и запись разговора, без шара (orb). Говоришь по-корейски, собеседник отвечает голосом; текст разговора сохраняется.

## Решения владельца (2026-11-16)

- Голос с микрофоном отменяет «звука нет» для этой функции (записано в `CLAUDE.md`).
- **20 минут в сутки** (`VOICE_DAILY_MINUTES=20`, поднято с 10 по слову владельца 2026-11-16: за 9 минут вышло около $0.45) и не больше 10 минут за один разговор; в окне видно «осталось N из 20 мин» и примерную цену.
- Orb не нужен: пока просто кнопка с микрофоном. Картинки владелец сгенерирует сам (сейчас значки рисует код, `components/voice/*.vue`, SVG).
- Разговор **остаётся включённым при закрытом окне**: сверху мини-плашка (таймер, микрофон, «закончить»), как мини-плеер у музыки.
- **Расшифровки хранятся полностью** в базе (звук не хранится): вкладка «История», удаление по кнопке.

## Как это работает

```
Браузер (микрофон, звук ответа) ──WebRTC──► OpenAI Realtime API
        │                                          ▲
        └─ 1. просит временный ключ ► наш сервер ──┘ настоящий ключ только в .env сервера
```

1. `POST /api/voice/sessions` (только владелец): сервер проверяет остаток минут, просит у OpenAI временный ключ (`POST /v1/realtime/client_secrets`, живёт 2 минуты, в запросе модель, голос, инструкция преподавателя, расшифровка речи, заголовок `OpenAI-Safety-Identifier`), заводит запись разговора и отдаёт браузеру ключ и номер.
2. Браузер соединяется напрямую с OpenAI: микрофон, канал `oai-events`, SDP на `POST /v1/realtime/calls`. Звук мимо нашего сервера.
3. События канала `conversation.item.input_audio_transcription.completed` (речь ученика) и `response.output_audio_transcript.done` (ответ) сайт отправляет на `POST /api/voice/sessions/:id/messages`.
4. Конец: `POST /api/voice/sessions/:id/end`. **Секунды считает сервер по своим часам** (не больше предела), недосчитанные (вкладку закрыли) тоже засчитываются до предела.
5. Сам разговор заканчивается при выходе времени или после 60 секунд полной тишины.

## Как устроен разговор (с 2026-11-16, после первых проб)

- **Сценки** (`backend/src/voice/scenes.ts`): «Свободный разговор», «Знакомство», «Что это?», «Где что находится», «Что делал(а) вчера», «В кафе». У каждой цель, шаги и 20–30 слов только из пройденного (тест сверяет слова со словарём `chat/curriculum.ts`). Выбор в окне перед началом, запоминается на вкладку. Новая сценка: запись в `SCENES`, фразы сверить по `docs/data.md`.
- **Инструкция короткая** (`prompt.ts`: девять правил, пройденная грамматика, слова и шаги сценки): мини-модель плохо держала длинную и список всех слов. Правила: беседа, а не заучивание; верную фразу подтверждать, ошибки не выдумывать; произношение по расшифровке не править; «не знаю» даёт готовый ответ; про непройденное только если ученик сам спросил.
- **Удерживай и говори** (по умолчанию, галочка в окне): автоопределение конца фразы выключено (`turn_detection: null`), микрофон открыт, пока кнопка нажата; по отпусканию сайт шлёт `input_audio_buffer.commit` и `response.create`, нажатие короче 0,4 с отбрасывается. Без перебиваний и эха. Обычный режим: `semantic_vad`, терпеливый.
- **Текст в окне:** корейские фразы собеседника крупно, нажатие открывает «Как собрано» (`SentenceBreakdown`). Под последней репликой ученика «Верно услышал? Да / Нет»: «Нет» даёт поле для правки, старая реплика удаляется (`conversation.item.delete`), вместо неё уходит набранный текст. Ответить текстом можно и без этого.
- **Разбор** (`review.ts`, `POST /api/voice/sessions/:id/review`): после разговора (и в «Истории») кнопка «Разобрать разговор»: текстовая модель помощника-чата (OpenRouter, `CHAT_MODEL`) читает расшифровку и пишет отчёт (что получилось, ошибки, что повторить, ошибки собеседника). Отчёт хранится в `voice_sessions.review` (миграция `20261116190000_voice_review`, только новый столбец), «Разобрать заново» пересоздаёт. Нужен `OPENROUTER_API_KEY`.
- Распознавание речи ученика: `gpt-4o-transcribe`, шумоподавление `near_field`. Без подсказки (`prompt`): она попадала в расшифровку как реплика ученика.

## Картинки окна (2026-11-16, набор владельца)

Лежат в `frontend/src/assets/voice/` (webp), подключены через `components/voice/voiceAssets.ts`: 40 иконок `icon_*.webp` (нарезаны из листа «Пастельная аниме-иконка: сакура и корейские мотивы»), `banner.webp` (девушка с котиком, верх листа) и `scene.webp` («Вишнёвый сад у ханока», 1280 px, фон середины чата под полупрозрачной подложкой). Значки сценок: `sceneIcon` (чат, люди, книга, карта, календарь, кофе).
**Как нарезано:** фон листа не прозрачный, а нарисованная серая шахматка (около 242–254, без цвета). Скрипт (был во временной папке, в репозитории его нет) искал на листе 40 цветных компонент, вырезал каждую с полем и заливкой от края делал фон прозрачным; у баннера допуск шире (в небе у башни шахматка с синим оттенком). Если нужно перенарезать, повтори этот приём (`sharp` есть в `backend/node_modules`). Белая «наклейка» вокруг иконок срезана вместе с фоном, видны только фиолетовые контуры.
Вид окна по макету владельца: заголовок со значком микрофона и подписью, вкладки со значками, баннер с облачком, карточки сценок со значками и галочкой, большой микрофон с волнами, строка остатка с часами.

**Два способа разговора (выбор в окне, «Как отвечать»):** «Голос OpenAI» (платно, живой голос, как раньше) и «Бесплатно» (Groq Whisper слышит, выбранная модель отвечает текстом, озвучивает `speechSynthesis` браузера: корейские куски `ko-KR` медленнее, русские `ru-RU`). Бесплатный разговор идёт без OpenAI, записывается в `voice_sessions` с `model = 'free'` и **минуты OpenAI не тратит** (`usedToday` такие строки пропускает). Работает только в режиме «удерживай и говори»: запись `MediaRecorder` уходит по отпусканию на `POST /api/voice/transcribe` (base64, до 3 МБ), потом `POST /api/voice/ask`.
**Модели** (`backend/src/voice/ai.ts`): Groq (`GROQ_API_KEY`, `GROQ_MODEL`, по умолчанию `openai/gpt-oss-120b`; Whisper `GROQ_STT_MODEL` `whisper-large-v3-turbo`), Gemini (`GEMINI_API_KEY`, `GEMINI_MODEL`, по умолчанию `gemini-flash-lite-latest`; имена с номером версии Google снимает, при «модель не найдена» взять другую из списка моделей), OpenRouter (прежние `OPENROUTER_API_KEY`, `CHAT_MODEL`). Все три отвечают по схеме OpenAI (`/chat/completions`, адреса: `api.groq.com/openai/v1`, `generativelanguage.googleapis.com/v1beta/openai`). Поставщик без ключа в списке не появляется (`GET /api/voice` → `providers`, `whisper`). Выбранная модель отвечает первой, при лимите или ошибке отвечает следующая.
**Проверено живыми ключами владельца (2026-11-16):** Groq `openai/gpt-oss-120b` отвечает за 1,3–1,9 с, Gemini `gemini-flash-lite-latest` за 1,6 с, OpenRouter `nvidia/nemotron...:free` за 4–8 с; Whisper `whisper-large-v3-turbo` за 0,35–0,42 с точно распознал корейскую (`저는 학생이에요`, `어제 학교에 갔어요`) и русскую речь (проба: голоса macOS `say`, не живая речь). `llama-3.3-70b-versatile` у Groq и `gemini-2.5-flash` у Gemini уже сняты (ответ 404), `gemini-flash-latest` 2026-11-16 висела от перегрузки (503/таймаут). Поэтому при ошибке **модель, которая отказала, показывается в окне («Не ответили: …»)**, а не молча подменяется. Список доступных моделей: `GET {base}/models` с ключом.
**Известные слабости бесплатных моделей:** Groq иногда пишет чтение корейского кириллицей и путает перевод короткой фразы (`안녕하세요?` как «Как вы?»), на что и нужна перекрёстная проверка: в пробе Gemini поймал оба случая. Пока чтение в тексте не вырезается кодом.

**Озвучка ответов в бесплатном режиме** (по слову владельца: браузерный голос «ужас»): `POST /api/voice/speak` озвучивает ответ голосом **Gemini TTS** тем же ключом (`GEMINI_TTS_MODEL`, по умолчанию `gemini-3.8-flash-tts`; адрес родной, `GEMINI_NATIVE_BASE`, не OpenAI-совместимый), русский и корейский в одной фразе модель читает сама. Новые модели отдают готовый WAV, старые сырой PCM (сервер сам добавляет заголовок). Голоса на выбор (`TTS_VOICES` в `ai.ts`, в окне «Голос»): Kore, Puck, Zephyr, Aoede, Leda, Charon, Fenrir, Orus. Готовые озвучки лежат в памяти сервера (150 штук, по тексту и голосу): повторные фразы бесплатны и мгновенны. В окне «Озвучка»: Gemini или браузер (запасной голос, ошибка озвучки показывается плашкой, браузерным голосом сама не подменяется). Проверено живым ключом: 2,5–3 с на фразу, Whisper распознал озвученную фразу дословно (`책이 책상 위에 있어요`); как голос звучит на слух, не проверено. Лимиты бесплатной озвучки Gemini не знаю (источники расходятся, у старой модели писали 15 запросов в день): смотреть в AI Studio. Запасной вариант на случай нехватки лимита: Edge TTS (голоса Microsoft, неофициально).
**Проверка ответа** (выбор «Проверка» в окне): `none` нет, `cross` другая модель читает ответ и пишет пометку «Проверка: верно/ошибка/не уверен», `self` та же модель. Пометка показывается под ответом. Разбор после разговора тоже идёт через выбранную модель.
**Лимиты бесплатных уровней** меняются, цифры смотреть в кабинетах Groq и Google AI Studio (в интернете расходятся: у Groq Whisper около 20 запросов в минуту и 2000 в сутки). Бесплатные уровни могут использовать вопросы для обучения моделей: личного в разговор не писать. Лимит минут OpenAI (`VOICE_DAILY_MINUTES`) на бесплатный режим не действует; счётчика запросов к бесплатным моделям пока нет (только ответы 429 и запасная модель). Серверные тесты: `tests/voice-ai.test.mjs` (поддельные Groq и Gemini).

**Другая модель:** кнопка «Спросить другую модель (бесплатную) про последний вопрос» под чатом (видна, когда есть твоя реплика): последний вопрос и до 8 реплик до него уходят в выбранную бесплатную модель (`POST /api/voice/ask`, при отказе запасная, при желании с проверкой), ответ добавляется жёлтой карточкой «Другая модель · Groq · на «…»», в историю не сохраняется. Нужен ключ хотя бы одной модели. Бесплатная модель читает только текст расшифровки и может ошибаться, ответы сверять.

**Ширина окна:** тянется за левый край (полоска слева, двойное нажатие возвращает обычную). Работает через `dragEdge` в `src/lib/dragdrop.ts` (GSAP Draggable, невидимая заготовка двигается, ручка стоит на месте), не уже 340 px и не шире окна, ширина лежит в `localStorage` (`voice_panel_width`). Проверено мышью в headless Chromium по CDP; на iPad и пером не проверено.

## Что нужно от владельца

1. **Ключ OpenAI в `.env` сервера** (`OPENAI_API_KEY=...`). Мне ключ не присылать, в чат и репозиторий не вставлять (правило 17). Перевыпустить, если попал в чат.
2. **Страница лимитов OpenAI сообщила «Limit not enforced»**: лимит $100 в аккаунте только предупреждает, запросы **не останавливает**. Реальная страховка это наши 20 минут в сутки; в кабинете OpenAI оставить оповещения.
3. **Проверить настоящую цену минуты** на странице цен OpenAI и поправить `VOICE_COST_PER_MIN` (сейчас 0.05 — прикидка; у `gpt-realtime-2` аудио $32 / $64 за 1 млн токенов, у mini дешевле, точные цифры источники давали разные).
4. **Руками в боевой Caddy** (его нет в git): в заголовке `Permissions-Policy` заменить `microphone=()` на `microphone=(self)` (`docs/hosting.md`, блок Caddy), перезагрузить Caddy.
5. **Картинки значков** (микрофон, запись, стоп, закрыть), если нужны свои: положить в `frontend/src/assets/voice/` (webp, как набор плеера) и сказать, подключу вместо SVG.
6. Слить ветку `feature/voice` в `main` (или сказать мне), когда решишь выкладывать: пуш в `main` сам запустит деплой. Миграция применится сама.
7. Проверить вживую: микрофон на ноутбуке, телефоне и iPad (Safari), качество корейской речи, расход.

## Что не проверено

Настоящий разговор с OpenAI (нужны ключ и баланс), микрофон в браузерах, iPad и телефон, Caddy на боевом сервере. Серверный тест `tests/voice-server.test.mjs` я локально не гонял (нет базы), его запустит CI. Названия событий расшифровки взяты по документации OpenAI GA (`response.output_audio_transcript`), у `conversation.item.input_audio_transcription.completed` страница документации имя не назвала, оно известно по общей схеме Realtime: если в живом разговоре реплики ученика не появятся в окне, смотреть именно его.

## Новая сессия: что делать по порядку (напоминания)

1. `git fetch && git checkout feature/voice && git pull`; прочитать этот файл и `docs/music.md` (образец).
2. Узнать у владельца: ключ положен? Caddy поправлен? Что показал первый настоящий разговор (реплики в окне есть? голос слышно? корейский верный?).
3. Если реплики ученика не сохраняются: открыть консоль браузера, посмотреть реальные имена событий канала `oai-events` и поправить `lineFromEvent` в `stores/voice.ts` (и тест `voice-panel.spec.ts`).
4. Прогнать по одному: `cd backend && npx vitest run test/voice-util.spec.ts`; `cd frontend && npx vitest run test/voice-panel.spec.ts --maxWorkers=1`; `node --test --test-concurrency=1 tests/voice-server.test.mjs` (нужна база, иначе смотреть CI), потом `npm run type-check` и `npm run lint`.
5. Дорожка улучшений (только по слову владельца): кнопка «Разобрать» у корейских фраз в истории (как в чате, `SentenceBreakdown`); свои значки вместо SVG; подпись «Слабые места» из ответов собеседника; режимы разговора («представиться», «в кафе») из пройденного; показывать ошибки отдельным цветом; удаление всех разговоров старше N дней; запись о новой возможности в «О платформе» (`about.ts`, скриншот) и шторку «Что здесь есть» (`guide.ts`).
6. После слова «слей»: PR или слияние в `main`, потом `gh run list --limit 4` (деплой автоматический), напомнить про `.env` и Caddy.
7. `docs/ideas.md` и `plan-and-fixes/plan-new.md` (на Mac): внести пункт «голосовой собеседник» и отметить статус.
