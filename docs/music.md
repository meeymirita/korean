# Музыкальный плеер

Сделано 2026-11-14. Личный плеер владельца: круглая кнопка с нотой на каждой странице (справа внизу над таймером), по нажатию справа выезжает меню с плеером (макет владельца, картинки из набора `music_player_assets_yuna`). Гостю и без входа по токену кнопки нет.

## Как это выглядит и работает

- **Кнопка** `components/music/MusicPlayer.vue` стоит в `app.vue` (внутри `ClientOnly`), поэтому есть везде, где сайт открыт под токеном владельца (внизу справа, левее «Таймера»). Значки: обычная, при наведении (розовая рамка), играет (розовая с живым эквалайзером).
- **Мини-плеер** по центру у самого верха экрана, пока меню закрыто, а песня выбрана: обложка, название, время, назад / пауза / вперёд, «развернуть». Круглая кнопка стоит внизу справа **левее «Таймера»**, а не над ним: над таймером всплывает его напоминание (`stm-note`), закрывать его нельзя.
- **Меню** шире прежнего: около 46% ширины страницы (`clamp(440px, 46vw, 900px)`). Обложка и название, полоса времени (перемотка), кнопки вперемешку / назад / играть / вперёд / повтор (все → одна → нет), громкость, **две вкладки: «Тихая музыка» и «Nightcore»** (с числом песен; решение владельца 2026-11-14; вкладка запоминается). Список показывает песни открытой вкладки. «Дальше» и «назад» идут по вкладке играющей песни, поэтому переключение вкладки музыку не сбивает. У песни «⋮»: «Переименовать», «В «Nightcore»» / «В «Тихая музыка»» (перенос между вкладками) и «Удалить» (с подтверждением, файл уходит в корзину Диска). Новые песни (файлом и по ссылке) попадают в открытую вкладку.
- **Добавить**: «Перетащи файлы сюда» или «Выбрать файлы» (mp3, m4a, aac, ogg, opus, flac, wav, webm, до 350 МБ каждый; несколько сразу, по одному) и поле «Ссылка» с кнопкой «Скачать» (YouTube и всё, что умеет yt-dlp). Под полем идут задания с полосой: передача файла на сервер в процентах, у ссылки «Скачиваю N%», «Узнаю название», «Переводю в m4a», «Сохраняю на Диск». Готовое исчезает через 3 секунды, ошибка остаётся с причиной и крестиком. Итог каждого задания приходит плашкой.
- **Не прерывается при переходе между страницами**: звук играет из `Audio` внутри хранилища `stores/music.ts`, а не из страницы. Полная перезагрузка страницы (F5, ссылка с другого сайта) звук обрывает: браузер не разрешает запускать звук сам, поэтому песня, место (раз в 5 секунд), громкость, повтор и «вперемешку» запоминаются (`localStorage`, ключ `music_v1`), и плеер ждёт нажатия «играть».
- Кнопки на экране блокировки и в наушниках (Media Session): играть, пауза, вперёд, назад, перемотка.

## Где лежат файлы

**Яндекс.Диск, папка `korean_music`** в корне приложения (как `korean_video`): `<id>.<расширение>` песня и `<id>.jpg` обложка. Сервер хранит только список в таблице `tracks` (миграции `20261114180000_tracks` и `20261114190000_tracks_category`, только добавляют таблицу и столбец `category`). Если Диск не настроен (локально без `YADISK_TOKEN`), всё лежит в `data/music/`; при `YADISK_DUMP_DIR` (тесты) на Диск пишется в эту папку.

Играет песня по **подписанной ссылке**: `<audio>` не умеет слать заголовок с токеном, поэтому `GET /api/music/<id>/url` (с токеном) отдаёт `/api/music/<id>/stream?e=<до когда>&s=<подпись>` (HMAC от токена владельца, 6 часов), а `stream` проверяет подпись и перенаправляет (302) на временную ссылку Диска: трафик идёт мимо сервера, перемотка работает. Без Диска сервер сам отдаёт файл с поддержкой перемотки (`sendFile`). Обложка так же (`/cover`).

## Скачивание по ссылке (yt-dlp)

`POST /api/music/url` `{ url }` запускает `yt-dlp` на сервере (по одному заданию за раз, при втором ответ 409): сначала название и длительность (`--dump-single-json`), потом лучший звук без перекодирования (`-f bestaudio[ext=m4a]/bestaudio`), обложка в jpg, процент по строкам `--progress-template`. Если формат не mp3/m4a/aac/ogg/flac/wav, `ffmpeg` переводит его в m4a (AAC 160 кбит/с). Дальше файл и обложка уходят на Диск, песня попадает в список. Настройки против блокировок: повторы, таймаут сокета 30 с, пауза между запросами 1 с, `--no-playlist`, JS-движок `node` для расшифровки ссылок YouTube.

- В образ бэкенда (`docker/backend/Dockerfile`) ставятся `ffmpeg` (apt) и готовый бинарник `yt-dlp` (без Python) с GitHub. **Обновляется при каждой пересборке образа**: YouTube часто меняется, и если скачивание вдруг перестало работать, достаточно `bash scripts/deploy.sh` (пересобирает образ).
- **YouTube может блокировать адреса серверов** («подтвердите, что вы не бот»). Тогда сайт покажет это текстом. Выход: положить файл cookies из браузера (формат Netscape, расширение «Get cookies.txt») в `data/youtube-cookies.txt` на сервере (путь можно сменить переменной `YTDLP_COOKIES`); сервер подхватывает его сам, перезапуск не нужен. Либо скачать на ноутбуке своим `yt-dlp` и добавить файлом.
- Переменные: `YTDLP_BIN` (путь к yt-dlp, по умолчанию `yt-dlp`; нужна тестам), `YTDLP_COOKIES`.
- Длительность и обложку из тегов загруженного файла определяют `ffprobe` и `ffmpeg`; если их нет, длительность покажет сам плеер.

## Лимиты и защита

- Загрузка с компьютера: `POST /api/music/upload` (multipart, поле `file`, необязательное `title`), файл пишется сразу на диск сервера (не в память), ответ 202 после получения, дальше идёт задание. Тайм-аут простоя 180 с, `server.requestTimeout` 30 минут (`main.ts`), маршрут входит в «тяжёлые» (40 запросов в минуту на адрес).
- **Caddy**: общий лимит тела запроса 60 МБ, для `/api/music/upload` 350 МБ (то же число `MAX_TRACK_MB` в `config.ts` и `MAX_TRACK_MB` в `stores/music.ts`) (`docker/caddy/Caddyfile`; в боевой Caddy вносится руками, блок в `docs/hosting.md`; проверено на настоящем Caddy: 70 МБ на этом маршруте проходят, на остальных 413; файл больше 350 МБ сайт отклоняет сразу, не начиная передачу).
- CSP: звук и картинки с Диска уже разрешены (`media-src`, `img-src` для `*.yandex.ru`, `*.yandex.net`, `nitro/plugins/csp.ts`).
- Все маршруты только для владельца, кроме `stream` и `cover`, которые требуют подпись.

## API (`backend/src/music`)

| Маршрут | Что |
|---|---|
| `GET /api/music` | `{ tracks, jobs }`: песни (с подписанной ссылкой обложки) и задания (сайт спрашивает раз в секунду, пока есть неоконченные) |
| `GET /api/music/:id/url` | `{ url }` подписанная ссылка на файл |
| `POST /api/music/upload` | файл с компьютера (поля `file`, `title?`, `category?`: `quiet` по умолчанию или `nightcore`), 202 `{ job }`; чужая вкладка 400 |
| `POST /api/music/url` | `{ url, category? }` скачать по ссылке, 202 `{ job }`; 400 плохая ссылка (только http и https) или вкладка, 409 уже идёт скачивание |
| `PATCH /api/music/:id` | `{ title?, category? }` переименовать и/или перенести в другую вкладку (`quiet` или `nightcore`); пустое тело 400 |
| `DELETE /api/music/:id` | удалить песню, файл и обложку (на Диске в корзину) |
| `GET /api/music/:id/stream`, `/cover` | по подписи: перенаправление на Диск или файл |

Задания живут в памяти сервера (после перезапуска список заданий пуст, незаконченное теряется; готовые песни в базе).

## Что не проверено

Настоящий YouTube с боевого сервера (проверяется только после выкладки), загрузка на настоящий Яндекс.Диск (локально Диска нет, проверено через `YADISK_DUMP_DIR` и локальную папку), iPad и телефон.
