# Резервные копии

Два слоя: **полный архив** (по кнопке и каждый день, уходит за пределы сервера) и **ночная копия** на самом сервере.

## 1. Полный архив на почту

В архиве: база, картинки (`uploads`, `thumbs`), файлы календаря (`docs`), обложка визитки (`public`) и `server/.env`. Всё сжато и **зашифровано** паролем `BACKUP_PASSPHRASE`
(AES-256, `openssl`): без пароля содержимое не прочитать ни на сервере, ни в почте.

Нужно один раз вписать в `server/.env` (значение в чат и git не попадает):

```
BACKUP_PASSPHRASE=длинная-фраза
```

- **Пароль архива** придумайте сами (`openssl rand -base64 30`) и **сохраните у себя отдельно** (менеджер паролей). Если сервер пропадёт вместе с `.env`, архив без этой фразы не открыть.
- Письма идут на почту из двухфакторной защиты; другой адрес: `BACKUP_MAIL_TO`. Нужны рабочие `SMTP_*`.
- Потом `systemctl restart progress`. В «Настройках» → «Резервные копии» кнопка **«Проверить отправку»** шлёт короткое письмо, а **«Сделать архив и отправить»** собирает и отправляет архив: видны этапы и процент, в конце плашка.
- Каждый день сервер делает то же сам (после 4 утра); выключить: `BACKUP_AUTO=0`, реже: `BACKUP_EVERY_DAYS=7` (раз в неделю). Письма с вложением до 18 МБ придут каждое утро; на сервере хранятся два последних архива.

Куда что попадает: на сервере в `server/data/export` (последние 2 архива), на почту письмом с вложением до 18 МБ. Если архив больше, он режется на части (до 5 писем),
а если не помещается и так, приходит письмо без вложения, а файл остаётся на сервере (скачать вручную).

Яндекс Диск по WebDAV пробовали: аккаунт отвечал 402 «требуется оплата», поэтому от него отказались. Когда архив перерастёт почту, подключите облако через `rclone` (см. `OFFSITE_RCLONE` в разделе 2).

### Как открыть архив

```
openssl enc -d -aes-256-cbc -pbkdf2 -iter 200000 -in korean-ДАТА.tar.gz.enc -out korean.tar.gz
tar -xzf korean.tar.gz
```

**Проверено 2026-10-30:** архив с почты открылся этим способом, внутри были `app.db`, `server.env`, `manifest.txt`, `uploads`, `docs`, `thumbs`, `public`; `PRAGMA integrity_check` базы вернул `ok`.
Дважды щёлкнуть по `.enc` бесполезно: файл зашифрован, нужен терминал и пароль. При неверном пароле будет `bad decrypt`.

Проверить базу из архива, не трогая сайт (нужен Node 22+):

```
node --no-warnings -e "const {DatabaseSync}=require('node:sqlite');const d=new DatabaseSync('app.db',{readOnly:true});console.log(d.prepare('PRAGMA integrity_check').get())"
```

После проверки **удалите распакованное**: в `server.env` лежат токен и пароли (`rm -rf korean-restore korean.tar.gz`).

Если архив пришёл частями: `cat korean-ДАТА.tar.gz.enc.part* > korean-ДАТА.tar.gz.enc`. Внутри `app.db`, `server.env`, папки `uploads`, `docs`, `thumbs`, `public`.

**Восстановление:** остановить службу, положить `app.db`, `uploads`, `docs`, `thumbs`, `public` в `server/data/`, вернуть `server.env` как `server/.env`, запустить службу.

## 2. Ночная копия на сервере

`scripts/backup.sh`: целостный снимок базы (с проверкой `integrity_check`), файлы жёсткими ссылками (одинаковые за разные дни хранятся один раз), конфиги Caddy и службы.
Хранит последние 14 копий в `/var/backups/korean`, пишет итог в `server/data/backup-status.json`.

Включить одной командой (от root, на сервере): `sudo bash scripts/install-backup-timer.sh --now`. Сначала можно посмотреть, что будет создано: `bash scripts/install-backup-timer.sh --print`.
Если таймер сломается или скрипт упадёт, сервер сам пришлёт письмо: «ночная копия не удалась» или «давно не делалась» (больше 36 часов; проверка раз в час, одно письмо на случай).

Вручную то же самое выглядит так (systemd-таймер, 03:30):

```
# /etc/systemd/system/korean-backup.service
[Service]
Type=oneshot
ExecStart=/bin/bash /var/sites/korean/scripts/backup.sh

# /etc/systemd/system/korean-backup.timer
[Timer]
OnCalendar=*-*-* 03:30:00
Persistent=true
[Install]
WantedBy=timers.target
```

`systemctl enable --now korean-backup.timer`. Переменные (`BACKUP_DIR`, `KEEP`, `OFFSITE_RSYNC`, `OFFSITE_RCLONE`) можно положить в `/etc/korean-backup.env`.

## Что показывает кабинет

| Сообщение | Что делать |
|---|---|
| не задан пароль архива / некуда отправлять | вписать `BACKUP_PASSPHRASE` и настроить почту (раздел 1) и перезапустить службу |
| «Почта ✗: …» | проверить `SMTP_*` командой `npm --prefix server run mail:check` |
| «Копия сделана более 30 часов назад» | проверить таймер: `systemctl status korean-backup.timer` (или установить: `sudo bash scripts/install-backup-timer.sh --now`) |
| «Архив не приходил на почту уже N дн.» (жёлтая плашка вверху кабинета) | архив идёт каждый день сам; проверьте почту и спам, нажмите «Проверить отправку», при необходимости «Сделать архив и отправить» |
