# Отчёт: тёмно-розовый редизайн (для проверки)

Дата: 2026-11-19. Ветка: `feature/dark-pink-redesign` (от `main`, свежий `main` влит коммитом «Merge main into the dark pink redesign branch»). В `main` ничего не слито, боевой сайт не затронут.
Образец дизайна: `urimal-landing.html` владельца (винный фон, розовое свечение за курсором, шапка-«таблетка», JetBrains Mono, белые кнопки).
Связанные файлы: план `docs/redesign-plan.md`, список картинок и промптов `docs/redesign-assets.md`.

## Что сделано

**Открытые страницы** (вручную, общая оболочка `frontend/src/components/site/PinkShell.vue`, токены в `assets/pink.css`):
главная `/`, `/about`, `/history`, `/me`, весь `/dict*` и `/ru*`, страница 404, окна «Что здесь есть» и «Запросить доступ».
Есть своя полоса прокрутки: чёрно-розовая линия справа, заливается по мере прокрутки, клик по ней прокручивает страницу.
Шрифт JetBrains Mono взят из файла владельца (`assets/fonts/JetBrainsMono-*.woff2`).

**Раздел `/korean`, игра и кабинет** (тема «Розовая», `ThemeMode 'wine'`, включена по умолчанию, светлая тема осталась в настройках):
- `assets/wine.css` собирается из `dark.css` скриптом `scripts/build-wine.mjs`;
- `assets/wine-components.css` собирается скриптом `scripts/build-wine-components.mjs`: он находит светлые цвета в стилях всех страниц и окон и выдаёт тёмно-розовый вариант только для этой темы;
- `assets/shell-pink.css` написан вручную: фон на всё окно, боковое меню, крошки, поиск, карточки главной раздела, страница игры, шторки.
Тесты `tests/docs-sync.test.mjs` следят, что оба сгенерированных файла свежие.

**Картинки**: иллюстрации Юны и фоны убраны из вёрстки (по решению владельца: картинки он рисует сам). Где что убрано и что вернуть, записано в `docs/redesign-assets.md`, раздел 11. Иконки интерфейса оставлены на месте, новые файлы кладутся под теми же именами.

## Как посмотреть

1. `npm ci && npm --prefix frontend ci` (если ещё не ставили), затем `npm run dev`, сайт на http://localhost:3000. Без запущенного сервера открытые страницы работают, страницы под токеном покажут экран входа.
2. С данными: демо-стек в Docker отдельным проектом (чтобы не трогать боевой): `docs/docker.md`, раздел «Данные для тестов», и `node scripts/demo-seed.mjs` (скрипт теперь сам берёт сеанс владельца, нужен `TOKEN` демо-сервера, не токен владельца).
3. Тема переключается в «Кабинет → Настройки»: «Розовая» (по умолчанию), светлая, тёмная, ночная.

- Не смотрел глазами: экзамен, помощник-чат, «Мои ошибки», метки, формы, «Культура», «Сайты», остальные вкладки кабинета, экран конца игры, PDF отчёта, карточка «поделиться». Цвета линий на графиках заданы в коде и не менялись.
- Страница `/growth` (появилась в `main` 2026-11-17, «Рост платформы») после слияния не оформлялась и не проверялась: в шапку добавлена только ссылка на неё. Её нужно привести к новому виду.
- В кабинете в шапке большая пустая розовая плашка, потому что нет картинки обложки.
- Не прогонялись: полный `npm test`, тесты с базой (CI), `npm run build`, проверка вёрстки на телефоне (`scripts/check-layout.mjs`), проверка перетаскивания в игре (правило 12 из `CLAUDE.md`).
- Старые светлые правила ещё не вычищены (последний этап плана).
- Картинки и иконки, баннеры Telegram, `og-image`, значки приложения, скриншоты «О платформе»: за владельцем, список в `docs/redesign-assets.md`.

## Что учесть при слиянии в `main`

- После слияния прогнать `npm test` целиком (около 3 минут, нужны PostgreSQL, Redis, Meilisearch) и `npm run build`.
- Если после слияния менялись стили: `node scripts/build-night.mjs && node scripts/build-wine.mjs && node scripts/build-wine-components.mjs` (тест подскажет).
- Правила в `CLAUDE.md` про пастельный дизайн («Решения владельца») нужно обновить под новый вид.
- Классы страниц не должны совпадать с глобальными (`.open`, `.card`, `.btn`, `.dot`): так на «О платформе» появился чёрный прямоугольник от старых правил `dark.css`.
