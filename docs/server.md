# Сервер: NestJS + SQLite

Папка `server/`, свои `package.json` и `node_modules` (у сайта свой корневой `node_modules`).
База встроенная: модуль `node:sqlite` из Node (нужен Node 22.18+ или 24.12+), обычный SQL без ORM. Файл базы:
`server/data/app.db` (в git не попадает).

## Запуск
- `npm --prefix server ci` (один раз), `npm run server:build`, `npm run server` (порт 3001, только `127.0.0.1`).
- Разработка: `npm run server:dev` (перезапуск при правках) и `npm run dev` для сайта (Vite проксирует `/api`).
- Настройки: `server/.env` (`PROGRESS_TOKEN=токен`, образец `server/.env.example`) или переменные окружения: `PROGRESS_TOKEN`,
  `PORT`, `DATA_DIR` (папка с базой и картинками), `IMAGES_QUOTA_MB` (нужна только тестам).
- Токен создать: `openssl rand -base64 24`.
- **Swagger** (`server/src/swagger.ts`, пакет `@nestjs/swagger`): `SWAGGER=1 npm run server` → `http://127.0.0.1:3001/api/docs`
  (описание в JSON: `/api/docs-json`). Все адреса API, сгруппированные по разделу адреса (`/api/notes/...` → `notes`); запросы прямо со
  страницы: кнопка Authorize, поле bearer, токен. Включается **только локально**: страница отдаётся мимо проверки токена, а Caddy
  пропускает наружу всё `/api/*`, поэтому в `server/.env` на боевом сервере `SWAGGER` не ставить. Для `/api/docs` при включённом
  Swagger мягче CSP (свои скрипты и стили), у остального API строгая. Тест: `server.test.mjs`, «health и Swagger».
- **`/api/health`** (открыт): проверяет, что база читается (`SELECT 1`): `200 {"ok":true}`, иначе `503 {"ok":false}` (подробности
  только в журнале сервера). На нём держится `scripts/deploy.sh`: сломанная база после обновления → откат.

## Таблицы базы
`meta` (очки `xp`, профиль, настройки, метки), `answers` (каждый ответ: время, слово, верно, источник, режим игры, очки, `detail` — JSON {q, a, y}: что спрашивали, верный ответ, что выбрано; столбец добавляется миграцией),
`words` (статистика слова: верно, неверно, серия, последний ответ, когда выучено), `days` (по дням: верных и всего),
`study_time` (секунды занятий по дням), `guests` (хэши гостевых токенов, имя, срок), `notes` (с картинками: `images`), `images` (название, описание; файлы лежат в `data/uploads` и `data/thumbs`),
`plans` и `plan_files` (записи календаря и их файлы), `today_sets` (наборы «Сегодня»), `sessions` (сеансы после кода из письма),
`site_images` (замены картинок сайта: ключ, файл или ссылка, сдвиг и приближение),
`coin_log` (журнал монеток: сумма, вид, уникальный `ref` против двойных выплат; подробно `docs/shop.md`),
`events` (входы, создание и отзыв токенов, неверные токены, картинки; последние 2000).

## API (все запросы с заголовком `Authorization: Bearer токен`, кроме `/api/health`)
- `GET /api/progress`: весь прогресс одним объектом (как раньше ждал сайт: `xp, days, all, time, words, sources, log, profile, settings`),
  собирается из таблиц.
- `POST /api/ops` `{ ops: [...] }` (с `reset` и `import` нужен заголовок `X-Confirm-Token`): пачка действий (до 500): `answer`, `reset`, `profile` (имя, картинка, `cover` — id обложки кабинета), `settings` (цель, темы, группы игры, закладки `marks`, свои сочетания клавиш `keys`: id пункта → `mod+alt+shift+KeyG`, не больше 40, без повторов), `time` (секунды занятий за день, 1–3600), `import`. Если хоть одно неверное,
  не применяется ничего (400). Правила (что выучено, как растёт серия) те же, что на сайте: `tests/parity.test.mjs` сравнивает.
- `GET /api/shop?day=`, `GET /api/shop/log`, `POST /api/shop/buy|use|claim`: магазин и монетки (только владелец, см. `docs/shop.md`); в ответе `POST /api/ops` теперь `{coins, combo, ready, news}`, действие `round` `{id, size, right}` засчитывает серию заданий.
- `GET /api/site-images` (открыто всем), `GET /api/site-images/file/:key` (открыто всем), `POST /api/site-images/:key/file` (multipart, до 12 МБ, сжимается до 1600 px, webp), `PUT /api/site-images/:key` (`{url}` только https и/или `{x,y,zoom}`), `DELETE /api/site-images/:key`: подмена картинок сайта, запись только владелец.
- `GET /api/chat` (`{configured, model, limit, left}`), `POST /api/chat` `{messages:[{role:'user'|'assistant', text}]}` → `{reply, left}`: помощник по корейскому (только владелец, ключ `OPENROUTER_API_KEY` в `.env`, подробности `docs/chat.md`).
- `POST /api/session`: запись входа в журнал. `GET/PUT /api/notes`: заметки целиком (у каждой `images` — до 10 id картинок).
- `GET/POST /api/guests`, `DELETE /api/guests/:id`: гостевые токены (создание возвращает токен один раз и требует `X-Confirm-Token`).
- `GET/POST /api/images`, `GET /api/images/:id/file|thumb`, `PATCH`, `DELETE`: картинки (JPEG, PNG, GIF, WebP до 50 МБ, всего до 1 ГБ;
  тип проверяется по содержимому, SVG нельзя). У картинки есть **назначение `kind`**: `gallery` («Картинки» в кабинете), `note`
  (вложение заметки), `cover` (обложка кабинета). `GET /api/images` отдаёт по умолчанию только `gallery`, `?kind=note|cover` другие;
  занятое место (`used`) считается по всем. `POST` принимает поля `caption` (название, до 200), `description` (до 1000) и `kind`;
  `PATCH /api/images/:id` меняет `caption` и/или `description`. Картинки `note` и `cover`, которыми никто не пользуется (нет в `notes.images`
  и не равны `profile.cover`), удаляются вместе с файлом и миниатюрой при сохранении заметок или профиля, но не раньше чем через сутки.
- `GET/POST/PATCH/DELETE /api/plans`, `/api/plans/:id/files`, `/api/plans/files/:fid/file|thumb`: записи календаря и файлы к ним; `GET/POST/DELETE /api/sets`: наборы «Сегодня».
- `GET /api/logs/app|caddy`: журналы (владелец). `GET /api/public/me|og.png|cover` открыты без токена, `GET/PUT /api/public/settings` и `POST /api/public/og` только владельцу.
- `GET/PUT /api/digest` (`{enabled, time ЧЧ:ММ, words 0–30, sentences 0–15}`), `POST /api/digest/test`: подборка слов и предложений на почту каждый день в своё время (владелец); время по часам сервера (часовой пояс: `timedatectl set-timezone Asia/Novosibirsk` и `systemctl restart progress`).
- `GET/PUT /api/reminder` (`{enabled, time ЧЧ:ММ, days [0–6], 0 — воскресенье}`), `POST /api/reminder/test`: напоминание заниматься (владелец); письмо одно в день, если до выбранного времени нет ответов, и только по отмеченным дням недели (пусто — каждый день); адрес `REMINDER_MAIL_TO` или почта защиты кодом.
- `GET/PUT /api/lesson` (`{enabled, weekday 0–6, time ЧЧ:ММ}`), `POST /api/lesson/test`: напоминание о созвоне с учителем (владелец); письмо в выбранный день недели в выбранное время, не смотрит на ответы за день; тот же адрес, что у напоминания заниматься.
- `POST /api/backup/run` (202), `POST /api/backup/test`, `GET /api/backup/status`: полный архив на почту и статус копий (владелец, см. `docs/backup.md`).
- `GET /api/db/tables`, `GET /api/db/tables/:name?limit&offset&q`: просмотр базы (хэши скрыты, длинные значения обрезаны).
- Роли: владелец делает всё; гость получает пустые ответы и его записи игнорируются, а картинки, база и токены ему закрыты (403).
  Ответы несут заголовки `X-Role` и `X-Guest-Expires`. Просроченный гостевой токен даёт 401 `{ error: 'expired' }`.

## Защита (`server/src/security.ts`)
- **Заголовки** на каждый ответ API: `nosniff`, `X-Frame-Options: DENY`, CSP `default-src 'none'`, `Referrer-Policy: no-referrer`,
  CORP/COOP same-origin, HSTS; `X-Powered-By` выключен.
- **Подбор токена**: 10 неверных токенов подряд с одного адреса (`RATE_BAD_LIMIT`) блокируют адрес на 15 минут (`RATE_LOCK_MIN`),
  в это время отвечает 429 даже с верным токеном; верный токен сбрасывает счётчик. В журнале событий `bad_token` и `ip_locked`.
  **Если сам заблокировал себя** (десять опечаток подряд): подожди 15 минут или перезапусти службу (`systemctl restart progress`),
  блокировки хранятся в памяти.
- **Частота запросов**: 600 в минуту с адреса (`RATE_LIMIT_PER_MIN`), загрузка картинок и создание гостей 40 в минуту
  (`RATE_HEAVY_PER_MIN`), иначе 429 и `Retry-After`.
- **Адрес клиента** берётся из `X-Forwarded-For` только если запрос пришёл с loopback (то есть от Caddy на этом же сервере);
  `trust proxy = loopback`. Сервер слушает только `127.0.0.1`.
- **Таймауты**: заголовки 15 с, обычный запрос 30 с, загрузка картинки 180 с (503 `timeout`), keep-alive 5 с; тело JSON до 4 МБ.
- **Картинки**: тип по первым байтам, SVG нельзя, до 50 МБ, ограничение разрешения 80 млн пикселей (защита от «бомб»), мало полей
  в multipart, общая квота 1 ГБ.
- **Повторный токен для опасных действий** (`auth/confirm.service.ts`): сброс прогресса и загрузка копии (`POST /api/ops` с действием `reset`
  или `import`) и создание гостевого токена (`POST /api/guests`) принимаются только с заголовком `X-Confirm-Token`, равным токену владельца,
  иначе 403 `confirm required`, и пачка не применяется. Неверное подтверждение считается подбором (отдельный счётчик от неверных входов,
  тот же лимит и блокировка, в журнале `bad_confirm`). Сайт спрашивает токен окном и шлёт заголовок сам.
- **Токен**: сравнивается без утечки по времени, строка длиннее 200 символов отбрасывается; токен короче 20 символов даёт
  предупреждение в журнале службы. Гостевые токены хранятся хэшами.
- Зависимости: `npm audit --omit=dev` в `server/` сейчас чистый (`multer` поднят `overrides` до 2.5.0, пока Nest не обновит свой). `webpack` в `overrides`
  закреплён на одной версии: без этого `npm ci` на старых npm (9–10, у меня и на хостинге) падал с «Missing: webpack from lock file», потому что
  npm 11 и более старые npm по-разному раскладывают конфликт peer-зависимостей. Проверка: `npx npm@10 ci --dry-run` в копии `package.json` и `package-lock.json`.
  Меняешь зависимости сервера: после `npm install` повтори эту проверку с npm 9 и 10.
  Раз в месяц делай `npm audit` и `npm outdated` в `server/`.

## Как смотреть, что в базе
1. Вкладка «База» в кабинете (только владелец): таблицы, строки, поиск, страницы по 50.
2. На сервере: `sqlite3 server/data/app.db` (например `SELECT * FROM answers ORDER BY id DESC LIMIT 20;`).
3. PhpStorm: Database → Data Source → SQLite → указать скачанный файл `app.db`. Ежедневные копии лежат в `server/data/backups/`.

## Сайт и сервер
Сайт (`stores/progress.ts`) показывает прогресс сразу из памяти, а каждое действие ставит в очередь `progress_outbox` (в браузере),
которая уходит на сервер пачкой через ~0,8 с. Сервер главный: при загрузке сайт заменяет свои данные теми, что в базе, но сначала
отправляет накопленное. Нет сети: очередь остаётся в браузере и уходит позже. Гость ничего не отправляет и ничего не сохраняет.

## Тесты сервера
Настоящий сервер на свободном порту с временной папкой (`tests/_server.mjs`): `server.test.mjs` (вход, гости, заметки, копии),
`progress-server.test.mjs` (в том числе время занятий и обложка), `images-server.test.mjs` (назначения, описание, очистка), `db-viewer.test.mjs`,
`security.test.mjs` (заголовки, блокировка подбора токена, лимиты, «бомба»-картинка). В `server.test.mjs` есть проверки обновления старых
баз (новые столбцы, разнос картинок по назначению). Лимиты в тестах меняют переменные `RATE_LIMIT_PER_MIN`, `RATE_HEAVY_PER_MIN`,
`RATE_BAD_LIMIT`, `RATE_LOCK_MIN`. `npm test` сам собирает сервер перед запуском.

**Обновление базы при запуске** (`Db.migrate`): к старым файлам добавляются столбцы `images.description`, `images.kind`, `notes.images`;
при добавлении `kind` картинки из заметок и обложка помечаются по назначению. Руками базу трогать не нужно.


## Двухфакторная защита (код из письма)

Включается владельцем в «Настройках» кабинета (блок «Защита кодом из письма»). Если включена, после верного токена сервер просит ещё код из 4 цифр, присланный на указанную почту.

- **Как работает.** Токен владельца остаётся как был. Если защита включена, а сеанса нет, любой запрос получает `401 {"error":"2fa"}` (кроме шагов входа). Сайт тогда показывает окно с кодом, шлёт
  `POST /api/2fa/send` (письмо) и `POST /api/2fa/verify {code}` (в ответ `session`). Сеанс (32 символа, в базе только хэш, живёт 30 дней) сайт добавляет в заголовок: `Authorization: Bearer <токен> <сеанс>`.
  Гостевые токены защитой не затрагиваются.
- **Код.** 4 цифры, живёт 10 минут, одноразовый, после 5 неверных попыток сгорает; новое письмо не раньше чем через 30 секунд; неверный код считается попыткой подбора (блокировка адреса, как у токена).
- **Включение без риска потерять доступ.** `POST /api/2fa/enable/start {email}` шлёт код на новый адрес, защита включается только после `POST /api/2fa/enable/confirm {code}`, то есть когда письмо дошло. Без настроенной почты включить нельзя.
- **Выключение и выход везде:** `DELETE /api/2fa` и `DELETE /api/2fa/sessions` просят токен ещё раз (`X-Confirm-Token`).
- **Почта.** Доступы в `server/.env`: `SMTP_HOST`, `SMTP_PORT` (465 или 587), `SMTP_USER`, `SMTP_PASS`, `SMTP_FROM`. Пароль в чат и в git не попадает.
- **Проверка почты:** `npm --prefix server run mail:check` проверяет вход в SMTP, а `npm --prefix server run mail:check -- адрес@почта` ещё и шлёт тестовое письмо (нужен собранный сервер).
- **Аварийный выход:** `DISABLE_2FA=1` в `server/.env` и перезапуск службы: вход снова по одному токену, настройки защиты сохраняются; после починки почты строку убрать.
- Таблицы: `sessions` (хэш, срок), настройки в `meta` (`twofa`). События в журнале: `2fa_sent`, `2fa_login`, `2fa_bad_code`, `2fa_on`, `2fa_off`, `2fa_mail_failed`.
- Код: `server/src/auth/twofa.service.ts`, `twofa.controller.ts`, `server/src/mail/mail.service.ts`; сайт: `composables/useTwoFa.ts`, `AuthGate.vue`, `cabinet/TwoFaBlock.vue`. Тесты `twofa-server`, `twofa-store`
  (в тестах письма пишутся в файл `MAIL_DUMP_FILE` вместо SMTP).
