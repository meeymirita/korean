# Журнал реализации инфраструктурного плана

Документ описывает фактические изменения этой работы. Он остаётся внутри `gpt/`; существующие Markdown-файлы проекта не редактируются.

## Текущий результат

Работа не завершена. Ветка содержит инфраструктурный каркас, частичный переход на модели Prisma и подключённый поиск Meilisearch. Runtime Prisma, интеграционные проверки и миграция прогресса ещё не завершены. Не запускай этот вариант в production и не загружай в него рабочую базу до завершения схемы, зависимостей, тестов и проверки восстановления.

## База данных и Prisma

- `backend/prisma/schema.prisma` описывает модели PostgreSQL и таблицы приложения.
- `backend/prisma/migrations/20261105000000_initial/migration.sql` создаёт начальную структуру.
- `backend/src/db/db.service.ts` содержит Prisma Client, транзакционный контекст на `AsyncLocalStorage` и параметризованный SQL-адаптер только для динамического read-only DB viewer.
- `backend/src/public/public.types.ts` хранит типы публичной карточки и её настроек.
- `backend/src/progress/progress.types.ts` хранит типы профиля и настроек прогресса.
- `backend/Dockerfile` генерирует Prisma Client, а перед запуском приложения применяет `prisma migrate deploy`.
- Через Prisma Client теперь работают заметки, блокнот, картинки, картинки оформления, календарные записи/вложения, гости, сессии, события, наборы на сегодня, напоминания, прогресс/аналитика, награды и пользовательские настройки.
- `Db` ещё содержит параметризованные SQL helpers только для динамического read-only DB viewer и проверки `SELECT 1`; обычные доменные запросы переведены на Prisma модели. Viewer использует список таблиц из `information_schema`, экранирует разрешённые имена и не меняет данные.

Владелец сообщил, что PostgreSQL-дамп из SQLite подготовит Claude и владелец загрузит его сам. Этот репозиторий не должен создавать второй конвертер. После импорта необходимо сравнить таблицы и контрольные значения с дампом, прежде чем считать перенос данных проверенным.

Обычные сервисы переведены на Prisma модели. Сборка всё ещё не проверяет типы настоящего сгенерированного Prisma Client: локально доступна только временная неполная декларация. Требуется проверить все обращения настоящим Prisma CLI и прогнать доменные интеграционные тесты на PostgreSQL.

## Кабинет и мониторинг

- `backend/src/admin/ops.controller.ts` и `ops.service.ts` предоставляют владельцу API состояния Compose-сервисов через docker-proxy.
- `frontend/src/components/cabinet/ServicesTab.vue` и вкладка `?tab=services` показывают состояние контейнеров и последние журналы выбранного приложения только владельцу.
- `backend/src/metrics.controller.ts` и `metrics.service.ts` добавляют метрики приложения.
- `docker-compose.yml`, `deploy/`, `monitoring/`, `backend/Dockerfile` и `frontend/Dockerfile` содержат начальный Compose-стек, прокси и конфигурацию мониторинга.
- `monitoring/prometheus.yml` содержит backend, node-exporter и self-scrape targets; `monitoring/grafana/dashboards/operations.json` содержит русскоязычную ops-панель.
- `docker compose config --quiet` прошёл с временным примером `.env`; сами контейнеры не запускались.
- Meilisearch индексируется владельцем из кабинета по публичному статическому каталогу. Общий поиск, слова, предложения и формы обращаются к backend API с постраничной загрузкой и локальным запасным поиском. Каталог игр также ищет по Meilisearch с локальным fallback.
- Для кабинета создан закрытый индекс `owner-materials`: backend собирает заметки и галерею из PostgreSQL, API проверяет роль владельца и возвращает только ID совпадений. Удаление/редактирование запускает объединённую отложенную переиндексацию; её можно запустить вручную в кабинете. Интеграционная проверка требует работающего Meilisearch и PostgreSQL.

## Текущие локальные проверки

- `npm --prefix backend run build` проходит только с временной локальной декларацией Prisma; это не проверка настоящего Prisma Client.
- Backend unit-проверки без `app.spec.ts` прошли: 16 тестов, fake SMTP integration пропущен из-за ограничений loopback. Полный набор всё ещё не стартует без собранного Prisma Client.
- `npm --prefix frontend run type-check` и `npm --prefix frontend test -- --run test/search-index.spec.ts` прошли; Nuxt сообщает предупреждение о robots для `/api/**`.
- `npm --prefix frontend test -- --testTimeout=15000` прошёл: 61 тест. Отдельный game suite также прошёл: 33 теста. При стандартном лимите 5 секунд три медленных game-теста превышали время.
- После подключения поиска каталога игр к индексу повторно проверены frontend type-check и тесты поиска; интеграционный запрос к живому Meilisearch не запускался.
- После подключения поиска игр полный frontend-набор запущен повторно: 9 файлов, 61 тест пройден; `git diff --check`, shell syntax, серверные integration-test файлы и статическая проверка Compose также прошли.
- Скрипты резервного копирования и установки systemd-таймера прошли `bash -n`; `--print` таймера не устанавливает службу.
- Тесты CI, fake SMTP интеграции и `pg_restore` подготовлены, но не исполнялись полностью в этой среде.
- Docker/Compose и dashboard JSON проходят статическую проверку; конфигурация backend services и логов покрыта unit-тестами. Сам Docker proxy, Grafana provisioning и реальные node_exporter метрики не запускались.
- Backup скрипт теперь пишет `backup.prom`, который node_exporter забирает через textfile collector; дашборд содержит панели нагрузки, задержки, ошибок, ресурсов VPS и статуса backup.

## Ограничения проверки

- Docker daemon доступен в пользовательском терминале, но сокет закрыт для текущей сессии агента.
- `npm view` и установка зависимостей не работают: `registry.npmjs.org` возвращает `EAI_AGAIN`; офлайн-кэш не позволяет установить `@prisma/client`, `prisma` или `ioredis`. В `node_modules` находится только локальная декларация Prisma для временной проверки TypeScript.
- В `backend/package-lock.json` пока нет записей пакетов Prisma. Обычная установка через npm, Prisma generate/migrate и проверка настоящего Prisma Runtime ещё не выполнены.
- Реальной SQLite-базы в checkout нет.

## Следующие шаги

1. Получить доступ к npm registry, установить Prisma, сгенерировать настоящий lockfile и Prisma Client, проверить схему/миграцию штатным CLI.
2. Проверить схему дампа, который загрузит владелец; довести все сервисы до корректного async PostgreSQL и убрать оставшиеся несовместимые SQLite-предположения.
3. Проверить резервные копии через реальный `pg_dump`/`pg_restore`, включая чистое восстановление структуры, данных и файлов.
4. Довести Redis/BullMQ и оставшиеся поисковые сценарии Meilisearch; сейчас Redis только описан в Compose и приложением не используется.
5. Выполнить интеграционный UI/API проход кабинета, PostgreSQL, Redis, Meilisearch, fake SMTP и Docker proxy в среде с контейнерами.
6. Выполнить два полных прохода проверок, после этого завершить документацию в `gpt/` и сверить все пункты `gpt/stack-ideas.md`.
