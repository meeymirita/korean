# План полной миграции стека

Цель: перевести приложение на PostgreSQL, применить Redis там, где он решает конкретную задачу, перенести текстовый поиск приложения в Meilisearch, показывать состояние контейнеров и логи в кабинете, настроить Prometheus/Grafana/node_exporter и сохранить данные, почту и резервное копирование.

Правило выполнения: идти по фазам сверху вниз; отмечать пункт `[x]` только после выполнения и проверки. Не удалять старые SQLite-файлы и старый способ восстановления до успешного переноса, проверки целостности, тестов и подтверждённого плана отката.

Ограничение документации по просьбе владельца: существующие Markdown-файлы репозитория не редактировать. План, журнал реализации и инструкции для этой работы хранить только внутри `gpt/`.

Ограничения проверочной среды на старте: в рабочем дереве нет `backend/data/app.db`; loopback listener тестов завершается `EPERM`; Docker CLI не имеет доступа к `/home/mira/.docker/desktop/docker.sock`; npm registry ранее был недоступен. Владелец отдельно подтвердил, что SQLite-дамп в диалект PostgreSQL готовит Claude и владелец сам загрузит его в PostgreSQL. Поэтому здесь создаются Prisma-схема и миграции структуры, но не конвертер/переносчик данных; сверка будет выполняться после загрузки подготовленного дампа. Запуск интеграционного стека требует доступа к Docker и зависимостям.

### Зафиксированная карта исходного проекта

SQLite содержит `meta`, `answers`, `words`, `days`, `study_time`, `guests`, `notes`, `images`, `plans`, `plan_files`, `today_sets`, `site_images`, `sessions`, `coin_log`, `nb_items`, `events`. Запросы идут через общий `Db` и затрагивают около 23 backend-файлов; найдено 6 транзакционных участков. SQLite-специфичные места помимо хранилища: `PRAGMA`-миграции, `sqlite_master`/`PRAGMA table_info` в DB viewer, `VACUUM INTO` в двух сервисах бэкапа и `changes` в результате UPDATE. Это всё должно получить PostgreSQL-эквивалент.

Текстовые поиски для реестра Meilisearch: основной поиск по разделам/грамматике/предложениям (`OverviewView`, `SearchWindow`, `data/korean/search.ts`), каталог слов/переводы/чтение/примеры (`words.ts`, `WordsView` и генераторы упражнений, если это пользовательский поиск), предложения (`SentencesView`), формы (`FormsView`), игры (`data/games.ts`), заметки и картинки кабинета, DB viewer и журналы. Фильтры по датам/тегам/типам должны остаться точными фильтрами и быть описаны отдельно от полнотекстового поиска.

Периодические задачи сейчас запускаются из `BackupService`, `DigestService`, `ReminderService`, `LessonService` и `BackupArchiveService`; письма идут через `MailService`/Nodemailer и нужны также для 2FA. Основная файловая копия — `scripts/backup.sh`, ручной архив и почтовая отправка — `BackupArchiveService`; текущие backup/server тесты напрямую используют `node:sqlite`, поэтому их фикстуры надо мигрировать вместе с runtime.
