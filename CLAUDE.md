# Контекст проекта для Claude (прочитай целиком перед работой)

Платформа **우리말** (название платформы; игра на слова внутри неё по-прежнему называется «Хлебушек») для изучения корейского, живёт на `https://korean.meeymirita.ru`.
Выделен из личного сайта «Магия воспоминаний» (`github.com/meeymirita/me`, там осталась только главная с меню и
цитатами и ссылкой сюда). Репозиторий: `github.com/meeymirita/korean`, ветка `main`, путь
`/Users/mira/Documents/projects/git_korean`. Общение с владельцем сайта — по-русски.
Главная (`/`) и вид всего сайта — по макетам владельца, подробности в `docs/home-and-theme.md`.

## Владелец и как с ним работать

- Учит корейский с нуля (университетский курс 서울대 한국어+ 1A + видеокурс 양쌤, уроки 1–30; живой учитель Лера,
  созвоны по субботам). Весь материал ведёт в Notion (workspace «Корейский язык»).
- Пишет о себе в мужском роде («я забыл», «я прошёл»). Не угадывай пол: избегай родовых форм о нём
  («ты написала/написал» → «напиши», «получилось»), в русских переводах предложений для «я» стоит нейтральное
  «ходил(а)».
- Правило программы: не забегать вперёд пройденного. Пройдены уроки 1–11 (есть в грамматике сайта),
  а также **прошедшее время** (он сказал, что прошёл сам, и позже принесёт конспект, поэтому оно разрешено везде:
  тренажёры, «Сегодня», игра). Будущее время (`-ㄹ 거예요`) НЕ проходили, не использовать. Уроки 12–30 в Notion
  пока пустые.
- Тон: просто, без лишней теории. Любит интерактив, задания «как в игре». Ответы стоит давать коротко, с итогом
  «что сделано, что проверено, что осталось».
- Решения владельца, которые нельзя ломать: **звук (озвучка) убран и не нужен** (кнопок «послушать» из макетов нет); шрифты на
  странице игры оставить прежнего размера; **никаких японских и китайских знаков** (韓国語, 言葉遊び и т. п.), декоративные
  надписи только хангылем; дизайн сайта — пастельный розово-голубой по макетам владельца (`urimal_landing`, `urimal_korean_dashboard`,
  `new_design`; он заменил прежние вес 500, засечки и фото уголком, см. `docs/home-and-theme.md`); название платформы **우리말**
  (в меню, на главной, во вкладке браузера); **никаких смайликов в строке тренажёров** и хлеба 🍞 в меню; картинки заметок и
  раздел «Картинки» это **два разных раздела** (у картинки есть назначение `kind`); вместо встроенных окон `confirm()`/`alert()`
  только свои модальные окна; **сброс прогресса и создание гостевого токена защищены повторным вводом токена**; фраза дня на главной
  меняется при каждом обновлении; значок вкладки — розовая ✳ (`public/favicon.svg`); после обновления страницы пользователь остаётся на той же странице, вкладке и прокрутке.
- **Правила кода, которые нельзя нарушать:**
  - запросы к серверу только через `fetchT` (`src/lib/http.ts`, таймаут 15 с, файлы 120 с), не через голый `fetch`;
  - подтверждения только через `askConfirm` (`composables/useConfirm.ts`); **опасные действия (сброс прогресса, загрузка копии, создание
    гостевого токена) только через `askTokenDo(опции, действие)`**: окно просит токен ещё раз и само выполняет действие, а ошибка
    («неверный токен») остаётся внутри окна, можно ввести заново; сайт шлёт его заголовком `X-Confirm-Token`, а проверяет сервер
    (`ConfirmService`); русские буквы в токене отсекаются до отправки. Новое опасное действие делай так же;
  - результат действий показывай плашкой
    `useToastStore().ok(...)` / `.error(...)` (плашки справа вверху, `ToastHost.vue`);
  - состояние страницы, которое должно переживать обновление, делай через `usePersisted` (sessionStorage) или `?параметр` в адресе;
  - окна и просмотрщики (`position: fixed`) выноси в `<Teleport to="body">`: внутри карточки с `transform` они «прилипают» к ней и
    дёргаются при наведении (так уже было с заметками);
  - **изменил страницу или добавил новую → обнови слайд и скриншот в «О платформе»** (`src/data/about.ts`, `src/assets/about/`);
  - **поменял слайды «О платформе» (`data/about.ts`) → поменяй и галерею в `README.md`** (заголовки, описания, картинки идут один в один, `tests/readme.test.mjs` следит);
  - **сделал идею из `ideas/`** → статус в `ideas/ROADMAP.md`, обновить `ideas/CURRENT.md`, запись в `docs/changelog.md` (`tests/ideas.test.mjs` следит за шаблоном и номерами);
  - **добавил открытую страницу → допиши её в `src/data/seo.ts` (заголовок до 75 символов, описание 60–190) и в `public/sitemap.xml`**;
    закрытую токеном страницу пометь `noindex` и добавь `Disallow` в `public/robots.txt` (`tests/seo.test.mjs` проверяет совпадение);
    открытую страницу добавь ещё и в `scripts/prerender.mjs` (`NAV`, `H1`, `BODY`): `npm run build` на выходе кладёт готовый HTML в `dist/<адрес>/index.html`
    (предварительная отрисовка для SEO, Vue потом заменяет её живым приложением; тест `tests/prerender.test.mjs`). Тег `yandex-verification` в `index.html` не удалять;
  - добавил игру или раздел → допиши его в шторку «Что здесь есть» (`src/data/guide.ts`);
  - окна поверх страницы держат порядок слоёв: окно подтверждения 500 и плашки 600 выше всего, просмотр картинки 300, окно грамматики
    50, поиск 45, окно заметки 60 (иначе окно «ныряет» под другое, так уже было с удалением картинки);
  - поменял сервер → перезапусти локальный сервер (`pkill -f "node dist/main.js"; npm run server`): старый процесс держит
    старый код, и сайт «не видит» новых возможностей.
- Рабочие привычки владельца: показывает правки по одной и быстро меняет решение («удали», «верни»), поэтому делай
  маленькими шагами и показывай результат скриншотом; временные файлы и скриншоты держи вне репозитория и удаляй; тесты в
  репозитории нужны (`npm test`); владелец сам проверяет на сервере после пуша.
- Коммиты и пуш делать только когда просят («закоммить и запушь»), отдельными коммитами по каждому действию.
  Сообщения на английском, повелительное наклонение, в конце строка
  `Co-Authored-By: Claude Sonnet 5.5 <noreply@anthropic.com>`. Перед пушем проверять, что каждый коммит
  собирается (временный `git worktree` + симлинки на `node_modules` проекта и `server/node_modules` + `vue-tsc --build` + `npm run build` + `npm test`).

## Стек и запуск

Vue 3 (`<script setup>`, TypeScript), Vite 8 (на rolldown, **esbuild нет**), Pinia, Vue Router (history mode),
шрифты самохостятся (`src/assets/fonts.css`). Скрипты: `npm run dev`, `npm run build` (type-check + сборка),
`npm run preview`, `npm test` (собирает сервер и запускает все тесты, см. `docs/progress.md`). Алиас `@/` → `src/`.
**Сервер** (`server/`, NestJS + SQLite, свои зависимости): `npm run server:build`, `npm run server`, `npm run server:dev`;
подробности в `docs/server.md`. Зависимости сервера ставить только внутри `server/` (`npm --prefix server ci`). Корневой
`node_modules` у проекта **свой** (раньше был ссылкой на соседний проект, отвязан 2026-10-30), пакеты в сайт ставить можно: `npm install <пакет>`,
после этого `npm test` и `npm run build`. Серверные пакеты внутри `server/`. Для временной проверки коммитов в `git worktree` в нём делай симлинк на
`/Users/mira/Documents/projects/git_korean/node_modules` и `server/node_modules`.

**Хостинг:** владелец сам заходит на сервер и запускает одну команду `bash scripts/deploy.sh` (делает всё ниже сам, проверяет `/api/health`, при ошибке откатывает; `--force`, `--no-restart`). Вручную то же: `git pull`, `npm run build` и, если менялся `server/`,
`cd server && npm ci && npm run build` с `systemctl restart progress` (**сервер обязательно перезапускать**, иначе сайт новый, а сервер старый); Caddy отдаёт `dist`, сервер работает как служба systemd.
Подробности и команды — `docs/hosting.md`.

предложений и букв); клик по результату справочника ведёт на `ref/<вкладка>?q=…`, `RichView` подсвечивает совпадения

страницы остаёмся на ней; без параметра — «Обзор»). Прокрутку после обновления возвращает `scrollBehavior` в `router/index.ts`.

## Как проверять изменения

- Автопроверки на GitHub (`.github/workflows/ci.yml`: типы, сборка, тесты, `npm audit` на Node 22 и 24) идут после каждого push; Dependabot раз в неделю предлагает обновления.
- Тесты: `npm test` (241 тест, около 8 секунд; для новой логики тесты обязательны). Типы и сборка: `npx vue-tsc --build`, `npm run build`.
- Визуально: headless Chromium из кэша Playwright
  `~/Library/Caches/ms-playwright/chromium_headless_shell-1248/chrome-headless-shell-mac-arm64/chrome-headless-shell`
  (`--screenshot`, или `--remote-debugging-port` и свой скрипт на Node 24 с `WebSocket` для кликов по странице).
- Тест TS-модулей без браузера: `tests/_load.mjs` (`load('/src/...')`; esbuild недоступен).
- Дев-сервер: `npx vite --port 5199`; после проверки обязательно `pkill -f "vite --port"`.
- На macOS нет `timeout` и `tac`; `sleep` в foreground блокируется — ждать через Monitor с циклом `for i in $(seq …)`.
- Временные скрипты и скриншоты держи вне репозитория и удаляй после проверки.
- Пересборка истории коммитов: `git rm --cached` попадает в следующий коммит, поэтому перед пересборкой делай
  `git reset <база>` и коммить через `git add -A -- <пути>`; каждый коммит проверяй в временном `git worktree`.
- Токен (`PROGRESS_TOKEN`) никогда не вставляй в чат и файлы репозитория. Нужен токен для проверки в браузере: читай `server/.env`
  прямо в скрипте, не выводя в чат; владельцу токен в буфер: `sed … | pbcopy`.
- Скриншоты «О платформе» снимай на **демо-данных**, а не на данных владельца: отдельный сервер
  (`DATA_DIR=<tmp> PORT=3002 PROGRESS_TOKEN=… node server/dist/main.js`) и `API_PORT=3002 npx vite --port 5198`, учебные ответы
  и заметки (без обложки, имени и личных картинок). Потом убери временный сервер и файлы.
- Тесты, которым нужен `_load.mjs`, обязаны вызывать `after(close)`, иначе `npm test` зависает. Таймеры в тестах двигай по
  секунде (`mock.timers.tick(1000)` в цикле): за один большой прыжок таймер занятий засчитает не больше 10 секунд.
