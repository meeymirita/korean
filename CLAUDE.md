# Контекст проекта для Claude (прочитай целиком перед работой)

Личный сайт «Магия воспоминаний» (тема «Провожающая в последний путь Фрирен») с разделом для изучения
корейского и игрой на слова. Репозиторий: `github.com/meeymirita/me`, ветка `main`, путь
`/Users/mira/Documents/projects/git_meeymirita`. Общение с владельцем сайта — по-русски.

## Владелец и как с ним работать

- Учит корейский с нуля (университетский курс 서울대 한국어+ 1A + видеокурс 양쌤, уроки 1–30; живой учитель Лера,
  созвоны по субботам). Весь материал ведёт в Notion (workspace «Корейский язык»).
- Пишет о себе в мужском роде («я забыл», «я прошёл»). Не угадывай пол: избегай родовых форм о нём
  («ты написала/написал» → «напиши», «получилось»), в русских переводах предложений для «я» стоит нейтральное
  «ходил(а)».
- Правило программы: не забегать вперёд пройденного. Пройдены уроки 1–11 (есть в грамматике сайта),
  а также **прошедшее время** (он сказал, что прошёл сам, и позже принесёт конспект, поэтому оно разрешено везде:
  тренажёры, «Сегодня», игра). Будущее время (`-ㄹ 거예요`) НЕ проходили, не использовать. Уроки 12–30 в Notion
  пока пустые.
- Тон: просто, без лишней теории. Любит интерактив, задания «как в игре». Ответы стоит давать коротко, с итогом
  «что сделано, что проверено, что осталось».
- Решения владельца, которые нельзя ломать: меню главной = список с группами слева («IT» и «Материалы по
  корейскому», без «Главной»), цитаты справа шириной 500px; внешних поддоменов (korean., alphabet.) нет, всё
  внутри; **звук (озвучка) убран и не нужен**; шрифты на странице игры оставить прежнего размера (страница
  растянута на весь экран, но шрифты не увеличивались).
- Коммиты и пуш делать только когда просят («закоммить и запушь»), отдельными коммитами по каждому действию.
  Сообщения на английском, повелительное наклонение, в конце строка
  `Co-Authored-By: Claude Sonnet 5.5 <noreply@anthropic.com>`. Перед пушем проверять, что каждый коммит
  собирается (временный `git worktree` + симлинк на `node_modules` + `vue-tsc --build` + `vite build`).

## Стек и запуск

Vue 3 (`<script setup>`, TypeScript), Vite 8 (на rolldown, **esbuild нет**), Pinia, Vue Router (history mode),
шрифты самохостятся (`src/assets/fonts.css`). Скрипты: `npm run dev`, `npm run build` (type-check + сборка),
`npm run preview`. Алиас `@/` → `src/`.

**Хостинг:** см. раздел «Хостинг владельца» ниже. Кратко: владелец сам заходит на сервер, делает `git pull` и
`npm run build`; Caddy отдаёт `dist`; рядом работает сервер прогресса как служба systemd.

## Данные и откуда они берутся (Notion → сайт вручную)

Сайт НЕ читает Notion сам. Данные лежат в файлах, обновляются по просьбе владельца («обнови из Notion»).

- **Словарь:** `dictionary.ts` — `RAW` (`n, k, r, t, s`: слово, чтение, перевод, пример), `CAT` (категории
  по слову), `SYN` (формы для поиска: «ем» → «есть»), `CATN`. Источник: база «🍞 Хлебушек (Словарь)»,
  data source `collection://37ac5bf0-cbf4-8069-b08d-000bef087df4`, страница `37ac5bf0cbf480298041ff8b5597df8e`.
  Поля: `🇰🇷 Корейский` (title), `Чтение`, `Перевод`, `Предложение`, `Категория` (мульти: Люди, природа, окружение,
  еда, место, животные, одежда, событие, тело, наречие, эмоции), ` Выучил` (чекбокс, везде «нет»).
  Пропускать строки «до этой пометки все слова напечатаны…» (служебная) и «🗑️ ДУБЛЬ …». Дубли слов склеены (оставлена
  первая запись). Сейчас 528 слов.
- **Как читать Notion:** SQL-режим `query_data_sources` быстро упирается в лимит (free-план, сбрасывается ~за час).
  Работает режим `view`: `view://37ac5bf0-cbf4-80c3-ae9f-000c49013c73` (вид «Словарь»), страницами по 100 строк
  через `start_cursor`. Порядок строк произвольный (не по дате). Чтобы найти новое, нужно прочитать все страницы
  и сравнить с `RAW` (так делалась сверка: строки переписывались в файл `слово|чтение|перевод|пример|категории` и
  сравнивались скриптом). Удобнее, если владелец создаст вид «Новые» с фильтром по дате.
- **Перевод у слов:** в `RAW.t` оставлена чистая форма без «→ 먹어요»; формы глаголов живут в `src/game/words.ts`
  (`D.V`, `D.A`: `[слово, чтение, перевод, настоящее, прошедшее, пояснение]`).
- **Грамматика:** `grammar.ts` (`G`, 26 карточек) ← база «Правила», `collection://39ac5bf0-cbf4-806e-92bb-000bab8cac14`,
  вид «Все правила» `view://3fdc5bf0-cbf4-8131-9bb5-000c2671196c` + карточки из «Полной памятки»
  (`3b8c5bf0cbf48163aa30f1a99db1a1d4`: `누구/누가`, `이/그/저`). Статусы: `ok` (пройдено) / `soon` («ещё рано»: `로`,
  `에게`, `에게서`). Блоки карточки: `['p'|'h'|'rule'|'formula'|'warn'|'tip'|'ok'|'pron'|'ex'|'tbl', ...]`, цвета в
  тексте `{o|…}` (есть 받침) и `{b|…}` (нет).
- **Справочники** (`pages.ts`): шпаргалка, разговорник (70 фраз со страницы «Разговорник» `39ec5bf0cbf481c59228c9890d58f12c`),
  хангыль, правила чтения, числа. Перенесены из старого `korean_all.html`, HTML собирается функциями.
- **Опечатки в самом Notion**, которые на сайте исправлены (в Notion остались): `폭 쉬어`→`푹 쉬어`, `젠가락`,
  `줘어요`, `모을라/모라요`, слэнг записан кириллицей (`хотябы`, `чхк`, `од`), `카피예요`, `슬ушать`, `덝다`, `피곰하다`.
- **Переводы предложений** — мои собственные (`translations.ts`, ключ = точная строка предложения, 517 штук): в
  Notion перевода нет. **Если добавляешь слово с новым предложением, добавь и перевод**, иначе разбор покажет
  предложение без перевода. Проверь, что нет повторов и что слова нового предложения разбираются (`?` = слова нет в
  словаре — это нормально, но лучше их добавлять).

## Разбор предложений (parse.ts)

`analyze(sentence)` режет предложение на слова/частицы/окончания: словарь (`LEX`) собирается из `dictionary.ts` и
форм глаголов из `forms.ts` + служебные слова (`FUNC`), частицы проверяются по правилу 받침 (`은/는`, `이/가`,
`을/를`, `이에요/예요`, `으로/로`…), есть `-해요`, числа, счётные слова, слова из двух частей («스포츠 센터»), имена.
Неизвестное → карточка «?». Покрытие примеров из словаря: 490 из 517 предложений целиком. Используется в
`SentenceBreakdown.vue` (клик по примеру в «Словах» и «Примерах») и в игре (разбор после ответа, переводы плиток).

## Игра «Хлебушек» (`src/game`)

`engine.ts` — императивный JS из старого `Hlebushek_Game.html` с `// @ts-nocheck`, работает на разметке
`markup.html` (вставляется через `v-html`), стили `game.css` (все правила с префиксом `.game`), состояние в
`localStorage` (`hleb_game_v1`: настройки, статистика, уровень/очки/цель дня, слабые слова). Режимы: микс, слово→
перевод, перевод→слово, формы, вопросы, частицы и счёт, **собери предложение**, **найди верное**, **напиши**.
Плюс блиц 60 с, **выживание** (3 жизни), **подсказка 50/50** (клавиша H, 3 на игру), уровень (звания от «Ученицы» до
«Великого мага»; уровень L нужен 50·L·(L−1) очков, +10/15/20 за ответ, +5 за каждые 5 в серии), **цель дня** 20.
Ошибки возвращаются чаще (вес по `S.miss`), у «собери предложение» повтор по зерну.

**Собери предложение** (`build.ts`): 3 уровня, шаблоны (простой — 2 слова, средний — 3–4, сложный — 5–7: время,
кто, с кем, где, «А и Б», отрицание `안`, заказ с числами). Корейский и русский текст строятся из одних и тех же
слов, частицы по 받침; лишние плитки с неверной частицей/временем/местом; допустимы разные порядки внутри групп
(`g` у чанков); ключ вопроса `b:уровень:время:зерно`. Кнопка «Показать переводы» (клавиша T) подписывает плитки,
клавиши 1–9 выбирают слово. Тесты: ~790 уникальных предложений, все разбираются `parse.ts`.

## Тренажёры и «Сегодня»

`/korean/trainers`: режимы «Найди пару» (`MatchGame`, таймер, рекорд в `localStorage` по ключу категория+размер)
и «Напиши перевод» (`TypingQuiz`, подсказка, печать листа). Категории словаря + «Грамматика»: глаголы,
прилагательные, вопросительные слова, вопросительные предложения (из `game/words.ts` через `forms.ts`).
Для глаголов/прилагательных задания: перевод, обратный, форма в настоящем, форма в прошедшем; для вопросительных
предложений — «вставь слово». `trainer.ts` — пул слов, проверка ответа (`acceptable`: «есть / кушать»).
`/korean/today`: 10 слов дня, правило дня, 8 заданий (`tasks.ts`: перевод, обратный, чтение, вставь слово, форма
глагола).

## Прогресс (общий для сайта) и сервер

- `src/stores/progress.ts` (Pinia): `record({word, ok, source, xp})` вызывают игра (`source:'game'`, через `hooks` из
  `GameView`), тренажёры (`'trainer'`, слово берётся через `statKey`: целые вопросительные предложения как слова не
  считаются), «Сегодня» (`'today'`, у `Task` есть поле `word`). Данные: `xp`, `days` (дата → верных за день;
  ключ = занималась), `words[слово] = {ok, bad, streak, last}`, `sources`. Слово «выучено» при `streak >= 3`
  (`KNOWN_STREAK`), «в процессе» при ответах, иначе «новое». В тренажёре «найди пару» слово засчитывается верным,
  только если в этом раунде в нём не ошибались.
- Уровни (`levels.ts`): 40 уровней, на уровень L нужно `30·L·(L−1)` очков, звания каждые 5 уровней: Искра, Огонёк,
  Свеча, Факел, Звезда, Луна, Рассвет, Созвездие, Вечность (нейтральные по роду). Цель дня — 20 верных ответов.
  Очки в игре: +10/15/20 за ответ (по уровню «собери предложение») и +5 за каждые 5 в серии; старые очки игры
  (`hleb_game_v1.all.xp`) переносятся один раз.
- Страница `/korean/progress`: карточки (уровень, серия дней, цель, выученные слова), календарь 8 недель, слова по
  темам, слабые слова, достижения, подключение сервера, копия файлом, сброс. Значок уровня есть в боковом меню
  раздела и на главной (под счётчиком дней).
- Хранение: `localStorage['progress_v1']`; при введённом токене (`localStorage['progress_token']`) — ещё и сервер
  `/api/progress` (GET/PUT, заголовок `Authorization: Bearer <токен>`). Свежее по `updated` побеждает; запись
  отложена на 1.5 с. Сервер: `npm run server` (токен берётся из `server/.env` — `PROGRESS_TOKEN=...`, образец `server/.env.example`; переменная окружения главнее файла; порт 3001, `127.0.0.1`), запись через временный
  файл, копия раз в день (30 штук), лимит тела 1 МБ, `dev`-режим Vite проксирует `/api`. Подробности запуска и
  Caddy — в `README.md`. Хостинг владельца позволяет запускать любые процессы; занимается он только с одного
  компьютера (синхронизация между устройствами не нужна, сервер нужен как резервная копия).
- Тесты, которые делались: юнит-тест хранилища через `ssrLoadModule` (заглушка `localStorage`, `pinia` из
  `node_modules/pinia/dist/pinia.js`), `curl` по серверу (401/200/400/413/405, копии), сквозной тест в браузере
  (ответы → localStorage → страница прогресса → токен → файл на сервере → новая версия с сервера подхватывается).

## Хостинг владельца (настроено 2026-10-29, работает)

- Сервер Ubuntu (`root@se-40678`), проект в `/var/sites/meeymirita_start_page`, сайт `https://meeymirita.ru`.

  `encode zstd gzip`, `handle /api/* { reverse_proxy 127.0.0.1:3001 }`, `handle { root * …/dist; try_files {path} /index.html; file_server }`.
  `try_files` обязателен для SPA (иначе прямые ссылки на `/korean/...` дают 404). После правки:
  `caddy validate --config /etc/caddy/Caddyfile` и `systemctl reload caddy`.
- **Сервер прогресса** — служба systemd `progress` (`/etc/systemd/system/progress.service`: `WorkingDirectory=` папка
  проекта, `ExecStart=/usr/bin/node server/index.mjs`, `Restart=always`, автозапуск включён). pm2 на сервере нет
  (владелец не ставил). Токен лежит в `server/.env` на сервере (не в git, права 600); данные в `server/data/`
  (`progress.json` и `backups/`). Диагностика: `systemctl status progress`, `journalctl -u progress -n 20`,
  `curl http://127.0.0.1:3001/api/health`, снаружи `curl https://meeymirita.ru/api/health`. Подключение проверено:
  на странице «Прогресс» статус «подключён · сохранено на сервере».
- **Как давать владельцу команды для терминала:** его терминал переносит длинные строки и портит вставку.
  Давай короткие команды (до ~70 символов), многострочные файлы собирай серией `echo '…' >> $F`, а не `cat <<EOF`
  (отступы при копировании ломают `EOF`), не вставляй команды с отступами в начале строк. Просить показать вывод
  (`cat`, `status`), прежде чем править чужой конфиг (в Caddyfile могут быть другие сайты).
