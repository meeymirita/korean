## Строгий порядок работы (для любой модели, читать первым)

Этот раздел написан 2026-11-11 по просьбе владельца для моделей, которые будут работать здесь дальше. Правила ниже не советы: выполняй их буквально и в этом порядке.

**Перед правкой**
1. Прочитай этот файл целиком, потом документ по теме из таблицы «Документация» и сами файлы, которые будешь менять. Не правь файл, который не открыл в этом разговоре.
2. Перед удалением или переименованием найди все использования (`grep -rn` по `frontend/src`, `backend/src`, `tests`, `frontend/test`, `scripts`, `docs`). Нашёл использование вне своей задачи: не ломай, скажи владельцу.
3. Описание расходится с кодом: верь коду, описание поправь. Не знаешь, как устроена библиотека: открой её исходник в `node_modules` или проверь `npm view <пакет> version time.modified`, а не пиши по памяти.
4. Ответ владельца на вопрос стоит **перед** вставленным текстом вопроса, а не после («да» над цитатой вопроса относится к этой цитате). Короткое «делай», «давай» относится ко всему перечисленному. Если понять нельзя, задай один вопрос и продолжай остальное.

**Как править**
5. Маленькими точными заменами. Для текста на русском пиши скрипт Python в файл во временной папке (не в репозитории) с проверкой `assert s.count(старое) == 1` перед каждой заменой и запускай его: так замена не попадёт не туда и не сработает наполовину. Большие файлы целиком не переписывай.
6. `frontend/src/game/engine.ts` (отрисовка и события) и `generators.ts` (генераторы заданий `gen…`) с 2026-11-11 проверяются компилятором (типы вопроса, состояния и хуков в `src/game/types.ts`): `@ts-nocheck` и `any` в них не возвращай, новое поле вопроса сначала допиши в `Question`. После любой правки в них всё равно гоняй игровые тесты (пункт 9): файлы большие, с общим состоянием.
7. Одно действие, один коммит. Не складывай разные задачи в один коммит и не трогай лишнего «заодно», кроме явной ошибки рядом (её чини и назови в ответе).
8. **Изменил или добавил что-то в одном месте: обнови все места, где это же написано** (карта в скилле `after-change`, решение владельца 2026-11-17: полдня ушло на разнобой в том, что где отмечено). После правки обнови: описание в `docs/` (или `docs/trainers/<режим>.md`), запись в начало `HISTORY`, сгенерированные файлы (скрипты перечислены в «Правилах кода»; график роста `/growth` обновляет `npm run growth`, тест следит), локальный `plan-and-fixes/plan-new.md`: в таблице «Статус» вверху поставь ✅ / ⏳ / ❌ (владелец смотрит её, решение 2026-11-14), в разделах ниже сделанное удали, новое допиши.

**Проверка (ноутбук владельца слабый: одна тяжёлая команда за раз, ничего не запускать параллельно)**
9. Затронутые тесты запускай по одному файлу:
   - данные и скрипты: `node --test --test-concurrency=1 tests/<файл>.test.mjs`;
   - сайт: `cd frontend && npx vitest run test/<файл>.spec.ts --maxWorkers=1`;
   - сервер без базы: `cd backend && npx vitest run test/<файл>.spec.ts`.
   Потом `npm run type-check` и `npm run lint`. Полный `npm test` и `npm run test:nuxt` целиком не запускай без нужды: ноутбук начинает тормозить. Серверные тесты с базой гоняет CI.
10. Смотри на строку `ℹ fail 0` или `Tests N passed`. Тест упал: не коммить, чини. Упал только тест, которому нужна база (`нужен TEST_DATABASE_URL`): это не твоя ошибка, скажи об этом.
11. Новое поведение покрывай тестом: данные тестом в `tests/`, экран или игру отдельным файлом в `frontend/test/` (в общий `game.spec.ts` не дописывай: он упирается в память).

**Что говорить владельцу**

## Правила кода

- Запросы к серверу только через `fetchT` (`src/lib/http.ts`, таймаут 15 с, файлы 120 с), не через голый `fetch`; заголовок `Authorization: Bearer ${progress.bearer}` (не `progress.token`).
  При отрисовке на сервере: `useFetch` с `baseURL: runtimeConfig.apiBase` и `timeout` (пример `PublicMeView.vue`).
- Подтверждения только `askConfirm`; **опасные действия только `askTokenDo(опции, действие)`** (повторный ввод токена, заголовок `X-Confirm-Token`, проверяет сервер).
- Результат действий показывай плашкой `useToastStore().ok/.error`.
- Состояние страницы, которое должно переживать обновление: `usePersisted` (sessionStorage) или `?параметр` в адресе (`useQueryParam`).
- Окна и просмотрщики с `position: fixed` выноси в `<Teleport to="body">`. Слои: подтверждение 500, плашки 600, просмотр картинки 300, окно заметки 60, окно грамматики 50, поиск 45.
- **Код выполняется и на сервере (Nuxt SSR):** в модуле и в `setup` открытых страниц нельзя трогать `window`, `document`, `localStorage`, `matchMedia`
  (только в `onMounted`, обработчиках или под `import.meta.client`). Переменная модуля на сервере общая для всех посетителей: состояние запроса в `useState`.
  Случайное на открытых страницах только от зерна (`useHomePicks`, `withSeed` из `lib/seeded.ts`), иначе «Hydration mismatch». Вход и прогресс из `localStorage` подставляются после оживления (`plugins/app.client.ts`).
- Сочетания клавиш: заняты ⌘/Ctrl+K и «/» (поиск), F (меню), Esc, 1–4 и Enter в заданиях. Новую клавишу сначала допиши в `src/lib/shortcuts.ts`.
- ✳ пиши с селектором `U+FE0E` (`✳︎`), иначе iOS рисует зелёный смайлик. `KNOWN_STREAK` живёт в `stores/progress.ts` и `backend/src/progress/progress.service.ts`: менять в обоих.
- **Режимы и тренажёры** (скилл `new-trainer`): любая просьба «добавь/измени в режиме X» (решение владельца, 2026-11-08) начинается с чтения `docs/trainers/<режим>.md` и файлов из его раздела «Файлы», потом правка, потом обновить описание. ## Порядок работы с материалами (так договорились с владельцем, 2026-11-04)

Тему и порядок задаёт только Лера (даёт грамматику на неделю, закрепляет на субботнем уроке): без неё сам ничего не добавляй и не предлагай новых тем.
Владелец разбирает тему сам в **десктопном приложении Claude** (другой чат, не этот): оттуда PDF с объяснением, задания, списки слов; он печатает и вклеивает в тетрадь.
**Учебник и файлы Леры** лежат в локальной `материалы/учебник/` (снимки Miro по темам в `miro/`, PDF Леры в `от-Леры/`; что где и чего не хватает: `материалы/учебник/ИНДЕКС.md`). Слова и имена из них вносятся на сайт только по слову владельца.
Сюда это попадает так:
1. Владелец кладёт файлы из десктопного приложения в локальную `материалы/ГГГГ-ММ-ДД/` (не в git; только файлы оттуда, `ЗАДАНИЕ.md` и картинок там больше нет). Слова в папку не кладёт: записывает на сайте (кнопка «Добавить слово») и присылает токен.
2. Говорит одной фразой: «карточки из материалы/…»; для слов и материалов присылает токен из панели «Входящие» (страница «Слова» → «API»).
3. Ты читаешь PDF и **дополняешь** карточку на сайте (`grammar.ts`), а не переписываешь (при этом выполни пункт про новую грамматику из «Правил кода»): что на сайте уже есть, оставляй, добавляй недостающее (ошибки, сравнения, порядок слов). Новая карточка идёт во «Мои карточки» (без `l`) со `st: 'soon'`. Статус `ok` ставь **только по слову владельца** («отметь пройденной»); он относится к вкладке «Мои карточки».
4. После смены статуса или словаря: `npm run sync`; тесты, коммит, пуш, напомнить про деплой.
Десктопное приложение сверяет новые слова на дубли по публичному `https://korean.meeymirita.ru/words.json` (после деплоя, кэш до ~15 минут). Пройденная грамматика и все предложения открыты для чтения: `/api/public/grammar`, `/api/public/sentences`. Ошибки из тетради теперь приходят от Claude из десктопного приложения как `mistake` в `POST /api/materials` (вместе с `task`) и видны во «Входящих» → «Материалы» и в `GET /api/learning` (решение владельца 2026-11-17); в код сайта (`grammar.ts`, словарь) они сами не попадают.

## Стек и запуск

Папки: `frontend/` (Nuxt 4, SSR, Vue 3, Pinia, `srcDir: 'src'`), `backend/` (NestJS 12 + Prisma + PostgreSQL, Node 26+ (LTS)), `docker/` (Dockerfile, Caddyfile, Prometheus, Grafana), в корне `tests/`, `docs/`, `scripts/`, `.github/` и `package.json` только для тестов
(три отдельных `node_modules`; корневой нужен тестам, `scripts/link-test-deps.mjs` делает `vue` и `pinia` ссылками на копии из `frontend/`). **Пути `src/...` везде считай от `frontend/`.**

- Установка: `npm ci && npm --prefix frontend ci && npm --prefix backend ci && npm --prefix backend run db:generate` (Prisma Client; тестам нужны PostgreSQL, Redis, Meilisearch и `pg_dump` 17+: как поднять, в `docs/docker.md`, последний раздел).
- Из корня: `npm run dev` (сайт, порт 3000, `/api` → `API_PORT`), `npm run server:dev` (API, порт 3001), `npm run build`, `npm run type-check`, `npm test`, `npm run sync` (обновить всё производное из данных) и `npm run sync:check`.
- Хостинг: Docker Compose (`docker-compose.yml`): сайт `127.0.0.1:3000`, API `127.0.0.1:3001`, PostgreSQL, Redis, Meilisearch, Prometheus, Grafana; боевой Caddy сервера остаётся прежним и ходит на эти порты. Обновление: `bash scripts/deploy.sh` (копия базы, сборка, откат сам). Перенос данных, копии, мониторинг: `docs/docker.md`; Caddy, защита, диагностика: `docs/hosting.md`.

## Как проверять

- CI на GitHub (типы, сборка, тесты, `npm audit`, на Node 26 LTS: те же образы Docker и тот же Node у владельца, одна проверка, решение 2026-11-14) идёт на каждый push; Dependabot раз в неделю предлагает обновления (крупные не сливать вслепую).
- Тесты: `npm test` (сборка сервера, Nest-тесты `backend/test`, Nuxt-тесты `frontend/test`, затем `tests/*.test.mjs`). Отдельно `npm run test:nest`, `npm run test:nuxt`. Быстро и без базы: `npm run test:quick` (все `tests/*.test.mjs`, которым не нужен сервер, по одному файлу, около минуты; можно часть имени: `npm run test:quick -- keyboard`).
  **Игровые тесты `frontend/test` разнесены по файлам** (`game.spec.ts`, `game-stories.spec.ts`, `game-variants.spec.ts`): один большой файл упирается в память Node (процесс падает с `SIGABRT`). Новые игровые тесты клади в отдельный файл.
- Покрытие (без порога, только цифры) раз в неделю считает отдельный workflow `Coverage` (`.github/workflows/coverage.yml`; запустить сейчас: `gh workflow run Coverage`, цифры на странице запуска). Локально: `npm --prefix backend run test:coverage`, `npm --prefix frontend run test:coverage` (`@vitest/coverage-v8`; полный прогон тяжёлый, на ноутбуке запускай с одним файлом: `npx vitest run test/<файл>.spec.ts --coverage --coverage.include=src`).
- Линтер: `npm run lint` (`oxlint` с типами, настройки `.oxlintrc.json`; ловит забытый `await` и неиспользуемое, идёт в CI). После `npm install` в корне, если тесты не находят `pinia` или `vue`: `node scripts/link-test-deps.mjs`.
- Типы и сборка: `npm run type-check`, `npm run build`. Тест TS-модулей без браузера: `tests/_load.mjs` (`load('/src/...')`).
- Визуально: headless Chromium из кэша Playwright (`~/Library/Caches/ms-playwright/chromium_headless_shell-*/…/chrome-headless-shell`), `--screenshot` или `--remote-debugging-port`.
- Демо-сервер: `DATA_DIR=<tmp> PORT=3002 PROGRESS_TOKEN=… node backend/dist/main.js`, сайт `API_PORT=3002 npx --prefix frontend nuxt dev --port 5198`,
  данные `API=http://127.0.0.1:3002 TOKEN=… node scripts/demo-seed.mjs`. Скриншоты «О платформе» снимай только на демо-данных. Потом убери сервер и файлы.
- **Локально с готовыми данными:** `bash scripts/local-demo.sh` поднимает свою базу (`kt-pg-local`), сервер (порт 3011) и сайт (`http://localhost:5198`, токен входа `local-demo-token-2026`), при первом запуске восстанавливает дамп `~/Documents/projects/korean-local-demo/korean_local.sql` (вне репозитория; учёба за месяц, входящие, проверки тетради); `down`, `dump`, `reset` (`docs/docker.md`).
- Вёрстка на телефоне: `TOKEN=… WIDTHS=320,390,768 node scripts/check-layout.mjs` (ничего не печатает, если всё в порядке); битые ссылки: `node scripts/check-links.mjs` (`BASE`, `TOKEN`, `EXTERNAL=1`).
- Swagger: `SWAGGER=1 npm run server` → `http://127.0.0.1:3001/api/docs` (только локально).
- На macOS нет `timeout` и `tac`; `sleep` в foreground блокируется: ждать через Monitor.
- **Linux-копия (ноутбук «вне дома», `/home/mira/Рабочий стол/korean/korean`):** `plan-and-fixes/`, `материалы/` и пути `/Users/mira/...` есть только на Mac; здесь их нет, открытое веди в `docs/ideas.md`. После клонирования: `npm ci && npm --prefix frontend ci && npm --prefix backend ci && npm --prefix backend run db:generate && npm --prefix backend run build`; без этого ~26 серверных тестов в `tests/` падают с `Cannot find module .../generated/prisma/client.js`, а с ними всё, что требует базы. Пути в тестах читай через `fileURLToPath(new URL(...))`, не через `.pathname` (кириллица и пробел в пути ломают `.pathname`). Chromium Playwright на Linux: `~/.cache/ms-playwright/`.

## Что осталось

Единый план: локальный `plan-and-fixes/plan-new.md` в корне проекта (не в git, репозиторий открытый). В нём всё открытое с указанием, откуда взят пункт и как его делать: ошибки и риски, типизация, тесты, сервер, вопросы к владельцу, учёба и материалы, большой словарь, идеи. **Здесь и в других файлах открытое не дублировать:** новый пункт дописывай в `plan-and-fixes/plan-new.md`, сделанный оттуда удаляй. Причины отложенных режимов остаются в `docs/trainers/`, сделанное по SEO и журнал в `материалы/сео/ПЛАН.md`.

Факты, а не задачи: видео, картинки и копии лежат на Яндекс.Диске (с 2026-11-06, `docs/disk-and-telegram.md`), Object Storage не нужен; картинки грамматики берутся с Диска (`korean_grammar`), в репозитории их нет, остальные картинки сайта остаются в `src/assets/`. Новая тема = группа слов и группа игр (`docs/game.md`).
